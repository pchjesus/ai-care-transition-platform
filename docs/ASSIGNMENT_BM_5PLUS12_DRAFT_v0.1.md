## [사실정보 — 교수님 요구 순서]

### 1. 대표(예비창업자), 팀 경력사항 및 실적

**사실 기반 기재 초안:** 간호학 전공 과정에서 의료기관의 진료·간호·퇴원 후 돌봄 및 지역사회 연계 업무에 관심을 갖고, 의료 학습·업무지원용 웹 시뮬레이터·UI/UX 프로젝트를 독립적으로 설계·개발한 경험이 있다. 기존 GitHub 프로젝트들은 의료현장 문제 발견, 사용자 흐름 설계, 버전관리·테스트에 관한 역량의 근거가 된다.

**근거로 별도 확인할 개인 프로젝트:** cardiac-electrophysiology-simulator, ventilator-simulator, prn-order-viewer, nursing-order-ux-research, design-kkakgi 등. 개발경험의 실제 역할·버전·시연 가능한 기능은 이력 정리 후 확정.

**미확보:** 실제 제품 전담 팀원, 의료기관 유료 납품 경력, 정식 임상 업무 경력, 임상검증 실적. 향후 필요 역할은 소프트웨어/보안·임상전문가·병원 영업·법률/규제.

### 2. 경쟁사, 비교

**공공의료연계망:** 대상자 초기·심층평가, 개인정보 활용 동의, 지역 자원 연계 및 모니터링을 지원한다. 홈페이지에는 EMR·행정 연동을 활용한 **양방향 의뢰/통합관리 추진**도 명시. 그러므로 평가·의뢰·양방향이라는 단어만으로 독점적 우위를 주장할 수 없다.

**AITRICS-VC:** 입원 환자의 EMR 기반 상태악화 위험 예측에 특화한 의료기기. 우리 제품의 주요 목적은 퇴원 후 복합돌봄 필요 확인 및 전환업무 관리로 다르다.

**Findhelp / Unite Us:** 사회서비스 검색, EHR 연동, 의뢰·결과 회신의 해외 선행 사례. Findhelp는 2026.9.2 발표에서 Epic 연동 의료체계 145곳 이상을 언급(기업 주장).

**차별화 가설(미검증):** 한국 퇴원연계 공식 서식 초안 자동작성, 원천정보 재활용·누락 검사, 기관별 평가·승인 담당자 설정, 의료진 분석/환자 설명 분리, 정책 버전 및 연계 업무 상태 추적.

실제 기존 EMR·공공 시스템이 해당 기능을 어느 수준까지 제공하는지 현장 조사 전 '없다'고 표현하지 않는다.

### 3. 시장 규모·성장률

**공식 배경지표:** 국가데이터처 「2026 고령자 통계」의 65세 이상 인구 **1,112만 5천 명, 21.6%**. 제5기(2024~2026년) 상급종합병원은 보건복지부 지정 **47곳**. 통합돌봄은 2026.3.27 전국 시행.

**사업군 참고:** 관련 보도자료의 2026년 3월 선정 병원 약 1,162곳과 4월 협약 실적 약 1,030곳은 날짜·정의가 다르므로 각각 출처를 병기해야 하며 **실제 구매 고객 수가 아니다**.

**정의할 직접시장:** 퇴원연계 전담 업무가 있고, 구매 예산·데이터 연계 권한·미해결 업무문제를 가진 의료기관 × 검증된 연간 계약금. 실제 TAM/SAM/SOM과 연평균 성장률은 아직 미산정. 고령자 인구 또는 건강보험 진료비를 SW 직접 시장으로 쓰지 않음.

### 4. 기술 스택·엔진

**초기 개발 예정:** HTML5 / CSS3 / Vanilla JavaScript(ES modules); 화면·도메인 로직·가상 데이터 저장소 분리. 데이터·평가규칙/출처·상태 검증·의뢰 워크플로·환자 공개정보를 모듈화.

**후속 서버 실험:** Firebase Authentication, Firestore, Security Rules, Emulator Suite, 필요 시 신뢰할 수 있는 서버 측 처리. 프로젝트·환경을 별도 격리하고, 초기에는 가상 환자만 사용.

**'AI'의 정확한 표현:** 초기에는 설명 가능한 규칙기반 돌봄 필요도/서식 검토 자동화. 의료진이 수정·승인. 비정형 의료기록에서 정보를 추출하거나 예측하는 학습 AI/LLM 모듈은 연구·검증 후 별도 도입 계획. 아직 검증된 학습모델이 개발된 것은 아님.

### 5. 확보 자산

**현재 확보:** 공개 GitHub 저장소(pchjesus/ai-care-transition-platform), README, BM·PRD·연구 백로그, R01 제도 검토, R02 공식 기능 조사 및 R05 합성 환자 데이터 전략. 기존 개인 개발 포트폴리오도 실제 내용 확인 후 경력 근거로 활용 가능.

**미확보:** 실제 환자정보·병원 EMR 접근, 임상 검증 결과, 정부·병원 공식 사업 제휴, 고객 계약, 유료 매출, 상표·특허 출원/등록.

### 6. 가격·비즈니스 모델

**자체 BM:** B2B2C 의료기관용 소프트웨어, 병원은 계약·지불자, 의료진·담당자는 실제 사용자, 환자·보호자는 서비스 이용자.

**수익 항목(가설):**
- 연간 병원 라이선스: 경량형 600만 원 / 표준형 1,800만 원 / 확장형 3,600만 원.
- 신규 구축비: 경량 300만 원 / 표준 800만 원 / 확장 별도 견적.
- 기관별 EMR 연동·유지보수·고급 분석은 실제 범위 확정 후 계약.
- 환자 기본 포털은 병원 계약에 포함하는 방향을 우선 검토.

**검증 전제:** 상기 숫자는 제안가/시장시세가 아니라 계산용 가정. 의료행위 환자소개/의뢰 실적에 따른 수수료는 초기 BM에서 제외. 수가·지자체 연계수당은 병원 사업수입의 가능성이며 창업기업의 직접 매출이 아님.

### 7. 특허·지식재산 현황

**현재 상태:** 등록·출원 완료 사항 없음(본 프로젝트에 관하여 확인된 범위). 의료기관별 환자정보 재활용 및 서식 매핑, 상태·권한 관리 구조에 대한 선행기술 조사 검토 예정.

향후: 사업명 상표 검색/출원 가능성, 코드 저작권, 오픈소스 라이선스, 대학/병원 협력 시 직무발명·공동개발 계약 확인. '출원 예정'은 실제 계획과 절차를 확정한 뒤 기재.

### 8. 1라운드 성과(목표)

**실적이 아닌 계획:**
1. 대상기관의 퇴원연계 AS-IS 흐름과 대체 시스템 비교표 작성.
2. 공식 서식·제도 및 논문·통계를 참고한 **완전 합성** 가상 환자 사례 4~6종 설계.
3. 의료진 워크벤치(A1) → 분석/상담(A2) → 검토·의뢰 → 환자·보호자 포털(B) → 성과화면(D)의 실행 가능한 웹 MVP 1종.
4. 화면·상태·서식 검사 자동 테스트 수행; 모의 업무의 처리시간·오류·이해도 측정 계획 및 가능하면 탐색 사용자 테스트.
5. 실제 고객·전문가 인터뷰 결과를 확보하면 참가자 수와 조사 방법 및 결과를 별도 기록.

확정 매출, MOU, '필요 응답률 91%' 등 외부 성과는 아직 없음.

### 9. 매출 목표·주요 일정

**기간:** 2026년 4분기 사업·제도 조사, 2027년 MVP/탐색 실증, 2028년 확장 가능성 검토, 2029년 반복 계약 가설. 일정은 과제용 도전 목표이며 외부 심의·전산 승인·규제에 따라 상당한 지연 가능.

**단순 계산용 표준형 계약 시나리오:** 연 이용료 1,800만 원 + 신규 구축비 800만 원.
- 2027년 신규 2곳, 연간 이용 2곳 가정 → 계약 관련 총매출 5,200만 원.
- 2028년 신규 6곳, 연간 이용 8곳 가정 → 1억 9,200만 원.
- 2029년 신규 12곳, 연간 이용 20곳 가정 → 4억 5,600만 원.

**원가 가정:** 연간 기관별 직접비 300만 원, 신규 구축 직접비 500만 원, 고정비 연 2.4억 원.
- 연간 반복 라이선스만으로 고정비 충당하는 단순 BEP = 16개 병원.
- 단순 영업손익: -2.04억 → -1.02억 → +0.96억. 3년 누적은 -2.10억.
- 계약 시작일, 회계상 매출인식, 인허가·인건비 증가·고객이탈·영업비·자금조달을 반영하지 않은 **모의 재무계획**이다.

### 10. 2라운드 진출시 사업비 사용 계획

**지원금이 1,000만 원이라고 가정한 예비 배분(확정 지급금 아님):**
- MVP 개발·시연: 400만 원
- 임상·제도 전문가 검토: 200만 원
- 사용자·시장 검증: 150만 원
- 보안·규제·법률 상담: 150만 원
- 예비비: 100만 원
- 합계: 1,000만 원

집행 항목 적격성과 인건비/개발비 인정범위는 실제 공고 확인 후 수정한다. 이 비용으로 의료기관의 임상 서비스 출시까지 가능하다고 주장하지 않음.

### 11. 멘토링 내용

**아직 실제 프로젝트 멘토링 기록을 입력하지 않음.**
교수님 또는 전문가의 구체적인 조언을 받은 뒤 **조언 → 반영해 실제 수행한 행동 → 측정 가능한 결과 → 다음 과제** 순으로 작성한다. 일반 과제 안내를 개인 멘토링 완료 실적으로 표현하지 않는다.

### 12. 자유 기입

**장기 사업화 계획:** 최초 의료기관의 가상데이터 기반 업무 시연·사용성 검증을 수행하고, 기관 공식 협력·보안·개인정보·임상·법률 승인 후 실제 실증 가능성을 검토한다. 이후 의료원 단위 확장, 표준화된 기관 연동 어댑터, 기존 EMR 업체와의 제휴를 중장기 성장 경로로 검토한다.

**제도적 경계:** 공식 지자체 통합지원 자격판정·서비스 배정을 자동 대체하지 않으며, 의료진 전문적 검토·수정·승인 기록을 유지한다.

**제품 개발 원칙:** 실제 환자정보 없이 공식 통계·논문 임상 패턴·직접 창작을 결합한 합성 사례, 설명 가능한 규칙·근거, 역할별 공개 범위, 데이터 계층 분리, HTML/CSS/JavaScript → 향후 Firebase 단계적 구조.

## [제출 전 반드시 확인할 사항]

1. 기업명과 대표자 실제 정보, 개발 포트폴리오 사실·실적 확인.
2. 시장규모의 구매 가능 기관 수, 실제 업무량, 병원 소프트웨어 납품 사례 및 가격 검증.
3. 2026.4 개정 사업안내의 **첨부 HWPX 신구조문/서식 변경을 원문 직접 대조**.
4. 공공의료연계망/EMR에 **이미 있는 자동서식·양방향 기능의 실제 구현 여부** 확인.
5. 정량적 AI 성능·실환자 데이터·공식 병원 제휴·멘토링 성과를 만들어내지 않음.
6. 3년 예상 손익을 현실적인 영업기간·계약시점·고객획득비·클라우드/연동비·현금흐름으로 재추정.
7. 과제 주교재의 특정 BM 유형 대응이 필요한 경우 책의 해당 모델 정의와 직접 대조.
