**한국 정책 배경:** 보건복지부는 2026-05-15 자료에서 4월 말 기준 전국 229개 시·군·구, 1,030개 병원의 협약 및 사업 초기에 보고된 601건의 병원-지자체 연계를 제시했다. 이는 **공적 연계체계가 존재한다는 근거**이지 당사 협약·수요·소프트웨어 구매의사를 뜻하지 않는다.

### 경쟁·차별화 가설
- **잘못된 포지셔닝:** 또 하나의 민간 장기요양/보조기구/호텔 추천 마켓플레이스, 지자체 판정 대체 서비스.
- **권장 포지셔닝:** 의료진이 검토·발행한 범위와 환자의 자발적 생활 준비를 분리하면서, *환자에게 무엇이 남아 있는지* 이해시키는 전환관리 인터페이스.
- **장기 확장:** 실제 조직·권한·동의·서버·계약이 확보된 뒤에만 의뢰 → 기관접수 → 회신 → 제공결과의 closed-loop 상태로 확대한다.

## 3. 보조기구·복지용구 독립 목업 정보구조 — `equipment-pathways-r13.html`

### 3-1. 목표와 제한
- 시나리오: **가상 근골격계 퇴원환자가 보행 보조기 관련 안내 이후 준비 경로를 알아보는 상황**. 진단·수술·처방의 구체적 내용 없음.
- 1단계 **필요 품목 확인 전제**: 이 목업은 특정 제품 필요성을 판단하지 않는다. 실제 품목은 담당 의료진의 개별 안내로 확인.
- 2단계 **이용경로 선택**: (가) 병원 대여·문의, (나) 장기요양 복지용구, (다) 장애인 보조기기·공공센터, (라) 일반 구매·대여. 각 경로는 **상호 대체 가능하거나 자동으로 자격이 있다는 뜻이 아니다**.
- 3단계 **문의 체크리스트**: 자격·품목·대여기간·배송·설치·비용·회수·위생/수리 조건 가운데 해당 경로에 필요한 확인사항 제시. 공식 출처 링크는 사용자가 자발적으로 열고, 앱은 정보 미전송.
- 완료 라벨은 `준비할 질문 확인` 등으로 제한. `예약완료`, `연계완료`, `의료진 추천` 금지.
- 광고·제휴·거래·실재고·가격·발행 데이터를 목업에 추가하지 않는다.
- 별도 저장 없음: DOM/메모리 선택만 사용; 페이지 새로 열면 초기화. 실제 이름·주소·생년월일·건강정보 입력 요구 금지.

### 3-2. 환자앱 적용 가능성 (아직 **반영하지 않음**)
1. 기존 환자 B '도움/생활·이동' 영역에서만 별도 정보형 안내로 진입하는 방안 검토.
2. 의료진 발행자료를 읽는 계층과 자발적인 생활물품 탐색 계층을 분리.
3. 병원 발행정보가 없으면 '의료진에게 품목 확인'을 가장 먼저 표시하고 특정 물품을 추천하지 않음.
4. 공적 경로 및 무료 대안을 민간 구매 버튼보다 불리하게 배치하지 않음.
5. 실제 거래 연계 시 별도 계약, 법적 검토, 개인정보 동의, 오류/취소/회신 프로세스 선행.

### 3-3. 전문가 워크스루용 과업 (실제 사용자 데이터 아님)
- E01: 합성 보행 보조기 준비화면에서 **장기요양 급여 가능 여부를 어디서 문의해야 할지** 발견.
- E02: **병원 대여/공공지원**과 민간 구매/대여를 구분.
- E03: 화면만으로 복지용구 **자격이 확정됐는지** 설명.
- E04: '질문 정리' 후 앱에서 **실제 구매·예약·병원 전송이 이루어졌는지** 설명.
- E05: 모바일 큰 글자 및 키보드로 경로 선택/뒤로/완료 확인.

## 4. Track B: 첫 실사할 세 모델과 질문
