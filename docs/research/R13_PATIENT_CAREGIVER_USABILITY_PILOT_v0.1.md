# R13 고령 사용자·보호자 과업 중심 사용성 파일럿 프로토콜 v0.1

> **R13 범위 조정(2026-10-23):** 모집 가능 인원을 고려해 1차는 AI/개발자 휴리스틱·인지적 워크스루로 실시하며, 사람 대상 관찰은 가능할 때 **1~2명 탐색적 파일럿**으로 축소한다. 이 수는 통계적 검증 표본이 아니며 실제 고령 환자의 대표성이 없다. 실제 연구자료를 수집·활용하기 전에는 지도교수/기관의 심의 또는 면제 필요 여부, 동의 및 자료 보관·삭제 절차를 확인한다. 아래의 5~8명은 원래의 **확장 목표**이고 완료 기준이 아니다. 구현된 이동 안내 과업은 [교통 UI R13 보충](./R13_TRANSPORT_USABILITY_SCOPE_20261023.md) 참조.

## 1. 연구 질문과 해석 경계

**주요 질문:** 고령 사용자·보호자가 독립 B 또는 의료진이 발행한 합성 계획의 연동 B에서, 설명자의 도움 없이 오늘 할 일·다음 일정·문서·도움 안내를 찾아 이해할 수 있는가? 알림과 승인/발행 범위를 과대해석하는 부분은 무엇인가?

- **결과 지표:** 과업 성공/부분성공/실패/평가불가, 오인 유형, 관찰된 막힘, 과업당 시간, 도움 요청 수준, 짧은 이해 확인, 만족도(설명적).
- **검증 대상이 아님:** 임상 위험도 예측 성능, 재입원 감소, 복약 이행/치료 효과, 병원 EMR 연동, 실제 예약·처방·돌봄기관 신청, 보호자 인증·권한, 서버 푸시.
- A2의 0~3은 **업무 검토 우선도**, 환자 임상 위험 점수가 아니다. 환자 공개 계획의 발행·철회·환자/입원건 격리 계약은 그대로 보존한다.
- 고령자의 사용 경험을 단일 집단으로 일반화하지 않는다. 소규모 관찰은 결함 발견과 다음 설계 방향 결정에 한정한다.

## 2. 시험 전에 통과해야 하는 게이트

1. **배포 스모크 체크:** `PHASE4_PUBLIC_SITE_SPOTCHECK_20261023.md`의 PUB-01~PUB-05 실제 기기/브라우저 확인; 연동 B를 사용할 경우 PUB-06~PUB-08까지 확인. 현재는 NOT RUN이며 이 문서 작성만으로 통과하지 않는다.
2. **시나리오 검토:** 고령 근골격계 퇴원환자 후보를 기본으로 하되 실제 수술/치료/복약 지시를 생성하지 않는다. 현재 `SYN-002` 등 합성 화면의 내용이 대상 과업을 담는지 확인하고 **전문가 검토를 거친** 가상 사례와 정답표를 확정한다.
3. **윤리·동의:** 수업 안의 내부 모의 실행과 외부 참여자 모집/면담을 구분한다. 실제 사람을 모집하여 연구 데이터를 수집·발표·활용할 계획이라면 **모집·기록 시작 전** 소속 기관 IRB/지도교수에게 심의·심의면제 필요 여부와 동의 절차를 문의하고 결과를 문서화한다. 교육·합성 데이터라는 이유만으로 자동 면제라고 판단하지 않는다. 동의 거부·중도 중단 불이익 없음.
4. **환경 분리:** 테스트 전용 브라우저 프로필, 합성 코드 `CARE2026`. 실제 이름·생년월일·병원기록·약 정보 입력 금지. 사용자 기기 기존 로컬 데이터 삭제 금지. 참여자별 독립 초기 상태를 만들고 검증한다.
5. **기술 사전 점검:** 네트워크, 글자 확대, PDF 열림, 알림의 전경/localStorage 범위, 저장 재열기, 모바일 터치, 외부 링크 차단 정책, 재현 화면 기록. 기능이 없는 항목은 평가불가로 표시하고 임의 구현하지 않는다.

## 3. 모집안·구성 (확정 아님)

- 첫 탐색적 라운드 **5~8명 목표**. 예: 65세 이상 스마트폰 사용 수준이 서로 다른 3~5명, 성인 보호자 경험자 2~3명. 실제 인원·표집은 윤리 검토와 접근 가능한 자원에 따라 확정.
- '실제 병원 퇴원환자'로 모집할 필요는 없다. 초기 UX 점검은 건강정보를 수집하지 않는 일반 고령 사용자·돌봄경험 성인에게 가상 시나리오를 제공하는 방식 우선 검토.
- 선정 시 디지털 사용 경험, 스마트폰/PC 선호, 돋보기·글자 확대 등 접근성 필요를 **최소한의 범주형 선택**으로 파악하되 건강 상태·진단 정보는 묻지 않는다.
- 사용자 한 명씩 개별 실시, 1명 진행자 + 가능하면 1명 관찰자. 고령자 20~30분 내외 목표(연구 설계상의 가정이며 실제 소요시간 아님), 피로 시 즉시 중단.
- 독립 B가 기본 시험 대상. **연동 B는 진행자가 사전에 합성 승인·발행 상태를 준비한 경우에만** 환자 화면 시험에 사용한다. 참여자에게 A3 의료진 승인 역할을 수행시키지 않는다.

### 진행자가 읽어줄 기본 안내문(예시)

> 지금 보시는 화면은 가상의 퇴원 안내 서비스 시연입니다. 실제 병원 기록과 연결되지 않고, 여기 적힌 안내를 본인의 치료·약 복용 지시로 사용하면 안 됩니다. 어떤 버튼을 눌러야 하는지 알아보는 시험이 아니라, 화면이 이해하기 편한지를 보는 시험입니다. 말씀하기 어려운 질문은 건너뛰거나 언제든 중단하실 수 있습니다. 화면이 막히면 그대로 말씀해 주세요.

이 안내문은 **IRB 심의/동의서 대체물이 아님**. 해당 절차가 필요한 연구에서는 승인된 안내·동의 양식을 사용한다.

| T07 | “방금 확인한 내용을 다시 떠올려 볼까요? 이해 확인이 있다면 수행해 주세요.” | 선택형 이해 확인, 설명과 행동 연결 | 표시된 질문을 이해하고 완료; 의료 지시 해석을 AI가 판정하지 않음 |

**별도 고위험 관찰(진행자용):** “앱에서 알림을 저장하면 화면을 꺼도 메시지가 자동으로 오나요?”, “화면에 나온 내용이 진짜 병원 처방인가요?”, “아직 발행하지 않은 안내도 환자에게 공개되나요?”를 참여자에게 설명 없이 묻고 **오인 여부만** 기록한다. 의학적 정답을 요구하지 않는다. 카카오톡·서버 푸시·실제 인증 등 존재하지 않는 기능을 있다고 유도하지 않는다.

**보호자 과업 보충:** 같은 가상 사례에서 “환자가 받았다고 생각하는 정보 중 보호자에게 설명하고 싶은 부분은 무엇인가요?”를 구술하도록 한다. **보호자용 계정·열람 권한·거부·허용 흐름이 현재 구현된 것으로 간주하지 않는다.** 실제 역할별 정보 공개 T6(기존 R00/R13 문서)는 기능 구현·안전검증 이후 별도 기술 과업으로 분리한다.

## 7. 분석 및 의사결정

- 집단별/과업별 독립 성공 `n/N`, 도움 후 성공 `n/N`, 평가불가 이유, 오류/오인 유형, 실제 계측 시간의 **중앙값과 범위**를 보고한다. 분모를 숨기지 않는다.
- 고위험 S0는 **1건만 있어도 우선 조사**하고 실제 환자 대상 전환 전 차단. S1은 재현 가능성을 확인하고 우선 해결, S2/S3는 빈도와 영향도로 우선순위화한다.
- 시험에 참가한 5~8명 수준에서 p값/임상 효과/일반 인구 전체 성공률을 주장하지 않는다. 성공률 목표치는 추후 내부 제품 기준으로 정할 수 있지만 통계적 안전성 입증 기준은 아니다.
- R00/R13 근거 문서의 '서면 퇴원안내 vs 웹앱' 교차 비교는 **내용·난이도가 유사한 비교 서면 자료 2종과 사례 정답표를 별도 개발·검토한 후** 시행. 지금은 비교자료 미완료로 수행했다고 주장하지 않는다.
- 임상적으로 중요한 증상 대응·약 변경 이해 평가는 의료진이 검토한 실제 **합성 지침**이 확보되기 전까지 관찰에 포함하지 않는다.
- 환자군·기기·리허설·IRB 결정·실제 참가자 수·성공/실패 로그를 구분하여 최종 보고서를 작성한다.
