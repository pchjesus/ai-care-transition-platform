# R13 — 환자·보호자 불편 탐색 전문가 검토 작업판 v0.1

작성: 2026-10-23 · **실제 고령 사용자 실험 NOT RUN**. 확인된 UI 사실 / 사용자 지적 / AI 가설은 구분.

## 1. 과제와 범위

- 목표: **새 기능을 더 추가하기 전에** 환자가 퇴원·외래 준비 흐름을 이해하는지, 의료기관 확인정보·시연용 정보를 구별하는지 검토.
- 대상: 독립 환자 B(`patient/index.html`)와 A3 승인·발행 계획을 소비하는 연동 B. 환자/보호자 두 관점. 합성 사례만 사용.
- 기술 기준: `main` 기준 환자·병원 앱 작동 및 `gh-pages` 배포 정상. R13 기술회귀와 **실제 고령 사용자 이해·행동**은 별개.
- 개발 브랜치 `feature/patient-mobile-drawer-krds-20261023`에는 58px 모바일 상단, 햄버거·사이드드로어, 상단 편의 기능 이동이 구현됨. Node 98/98, 독립 B 모바일 시나리오 및 연동 B 미저장 알림 이탈보호 시나리오 각각 검증 PASS. **아직 main/gh-pages 배포되지 않았음**; 실제 사용성 평가 기준 버전 지정 필요.
- 검토는 (a) 문구/정보구조/키보드/컨트롤 전문가 휴리스틱, (b) 과업을 초보 사용자처럼 수행하는 인지적 워크스루, (c) 가능하면 실제 사용자 1~2명의 비유도성 관찰로 분리. 사람 대상 연구 자료로 활용 전 기관/지도교수의 윤리·동의 검토.

## 3. 인지적 워크스루: 과업보다 물어볼 판단 4개

각 과업마다 다음 네 질문을 순서대로 기록:
1. 첫 화면에서 **무엇을 해야 하는지 알 수 있는가?** (목표)
2. 다음 버튼·카드를 **발견할 수 있는가?** (가시성)
3. 버튼이 어떤 일을 할지 **예상할 수 있는가?** (의미·오인)
4. 클릭 후 일이 완료됐는지, 잘못됐는지 **알 수 있는가?** (피드백)

## 4. 테스트할 대표 흐름(권장 순서)

- **T01 독립 B 진입:** 체험 코드 입력 → ‘오늘 필요한 첫 행동’ 찾기.
- **T02 일정:** 발행된 확정 일정과 미확정/시연 안내 구별하기.
- **T03 문서:** 안내자료(PDF) 찾기 → 열람 → 본문으로 돌아오기.
- **T04 알림:** 개인 준비 일정 설정 → 저장, 앱 종료 후 알림 동작 예상 설명.
- **T05 모바일 메뉴:** 햄버거 열기 → 글자 확대 → 내 정보 찾기 → 닫기/하단 5탭.
- **T06 미저장 보호:** 알림 설정 중 이동 → 취소 시 입력값 보존 확인.
- **T07 이동:** 병원 주소 확인 → 지도 연결/미확정 목적지 차이 판단.
- **T08 택시:** 출발지·방문 병원/보조기구/내릴 때 필요한 도움 설정 → 최종 확인 → ‘실제 호출 됐나요?’ 질문.
- **T09 보호자:** 보호자가 어떤 정보를 볼 수 있는지와 개인정보 동의 판단.
- **T10 숙박·보조기구 컨셉 카드(아직 개발 X):** 광고/공공 서비스/의료진 안내의 차이 구별. 화면 제작 전 텍스트 시안으로 가능.

관찰 항목: 화면별 첫 클릭, 오탭, 되돌아감, 혼자 해결/힌트 후 해결/실패/N.A., 시간, 이해/오인 발언, 글자 확대 필요도, 몸을 기울이거나 확대하는 행동. 실제 사용자 행동 데이터는 없으며 AI는 추측만 할 수 있다.

## 5. 결함 우선순위

- **S0 안전:** 미발행 의료정보가 발행된 것처럼 보이거나 실제 처방·예약·택시/숙박 서비스 제공을 오인, 환자/입원건 정보 노출 → 시연 중단·즉시 수정 후보.
- **S1 과업 중단:** 1차 필수 할 일/외래 안내/알림/도움 사용 불능 또는 저장 손실.
- **S2 반복 혼란:** 메뉴 발견성, 장문 설명, 오탭, 뒤로가기 반복, 보조기구/도착 후 도움 혼동.
- **S3 경미:** 비핵심 간격·색·애니메이션.

미관만으로 우선순위를 정하지 않는다. 심각도, 발생 가능성, 수정 범위, 안전 계약 영향, 확인된 사용자 증거를 각각 표기.
