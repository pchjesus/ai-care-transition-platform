# A3 다중 원천근거 연결 — 합성 MVP 변경 기록 (2026-10-22)

## 사용자 요구
- A3 환자 안내의 생활·이동 지원처럼 여러 분야의 가상 원천 기록을 **한 계획 항목에 2건 이상 연결**.
- 작성 의료진 / 지정 최종 승인자 / 환자용 B의 역할 차이 안내.
- 현재 단계의 드롭다운 역할 전환은 실제 의료인 인증이 아닌 합성 시연임을 유지.

## 변경 내용
- 신규 선택형 `draft.items[].sources: string[]`. 기존 `draft.items[].source: string`는 배열 첫 항목(대표 출처)으로 함께 유지하고, 이전 기록에 배열이 없는 경우 기존 source 한 건으로 읽는다. 기존 저장 객체 전체를 변경하지 않으며 `schema: 2` 유지.
- 계획 편집: 연결된 자료 여러 건을 제목·확인상태·자료 보기·개별 연결 해제 버튼과 함께 보여준다. `+ 기록 추가 (n건)` 선택창을 연 후 선택한 기록은 대화상자를 닫지 않고 추가/제거할 수 있다. 최대 12건. 기존 미해결 문제(issues)용 단일 근거는 이번 범위 밖이다.
- 연결/해제는 모두 검토 완료를 해제한다. 승인·검토 요청 중 편집하면 기존 A3의 승인 무효화 규칙을 따르고, 변경된 배열까지 `fingerprint`에 포함된다. 저장 실패/다른 탭 충돌은 변경 전 복사본으로 되돌린다.
- 저장 계약: 배열 중복·비문자 값·대표 source와 불일치·상한 위반은 읽기에서 거절한다. 발행 전에는 모든 연결 근거가 **같은 환자/입원건/해당 항목에 맞고 CONFIRMED**여야 한다. 선택 기록 중 하나라도 미확인/상충이면 승인 불가.
- 기존 A3 승인·발행 스냅샷은 수정하지 않는다. 환자용 B의 공개 allowlist에 원천 기록 ID나 감사 기록을 노출하지 않는다.

## 검증
- PASS: 실제 A2 규칙·어댑터·A3 데이터/출처·workflow·storage 모듈을 읽어 함수로 실행한 24개 조건. 초기 합성 사례/구 단일 데이터, 복수 확인 출처, 타 환자·미검토·중복 거부, 대표 불일치, 전체 근거 삭제, 개정 발행본 보존, 발행 공개 allowlist, 저장·복원, A3 앱 구문.
- NOT RUN: 저장소 Node test 전체, Playwright/Chromium 클릭/반응형, 실제 기기, 실서비스 승인·권한. 직접 검사 PASS를 전체 E2E PASS로 주장하지 않는다.
- 기존 초기화 환자 데이터와 과거 발행본 해시를 변경하지 않았다. 다중 목록은 저장된 레코드를 사용자가 편집할 때만 추가된다.
- 역할 전환 UX는 전 회차에 추가한 화면 안내만 유지; 별도 의료진 계정·검토 접수 시스템은 신규 구현하지 않음.
