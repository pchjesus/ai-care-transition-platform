작업 브랜치: `chat/a3-patient-b-integration-v1`. 인수 SHA: `3a572fd76dcb9816deef84129c6528b0949936f6`. 비교: `codex/hospital-unified-v1@913f0c0d80651349aaef85da660e92631ca7233a`. [Draft PR #3](https://github.com/pchjesus/ai-care-transition-platform/pull/3)의 같은 브랜치에 반영한다. 최종 SHA는 이 보고서를 포함하는 최종 커밋과 원격 브랜치 HEAD로 식별한다.

합성 데이터·동일 브라우저 origin의 개발 MVP다. 실제 본인인증·서버 권한·EMR·Firebase·임상 검증을 구현하거나 주장하지 않는다. `main`·PR #1/#2·독립 B 원본·`gh-pages`·배포 설정은 변경하지 않는다.

## 구현·보완

- **발행 계약 재사용·보강:** `shared/publication.js`가 A3 영속 저장소에서 현재 유효 발행본만 공개 allowlist로 투영한다. 환자/입원건, 평가 ID, 버전, 승인자/역할/시각·지문, 실제 공개 스냅샷의 일치를 확인한다. 개정 중에는 더 높은 버전의 초안과 기존 유효 발행본을 구분한다. 형식에 맞지 않는 공개 항목은 A3에서도 발행 전에 차단한다.
- **PDF 연결:** 새 `shared/published-documents.js`가 A3의 검토 완료된 실제 PDF 바이트를 SHA-256으로 대조하고, 환자·입원건·발행·문서 ID별 IndexedDB에 보관한다. 바이트 저장 성공 및 대기 중 원본/역할/환자/저장 상태 재검증 후에만 A3 발행을 확정한다. B는 현재 유효 발행본의 문서만 열고, 해시·크기·이름·식별자와 읽기 완료 후 발행 상태를 다시 검사한다. 외부 URL이나 다른 시연 PDF를 임의 연결하지 않는다. 해시·manifest는 환자 공개 데이터에 복사하지 않는다.
- **B 자료 인터랙션:** 모달 PDF 미리보기, 새 창 열기 링크, 실제 파일 다운로드, 오류/미제공 안내를 연결했다. B 새로고침 후에도 승인된 원본을 읽는다. 철회/새 버전 전환 시 모달과 앱의 Blob URL을 제거한다. 개정 시 환자 공개 PDF는 재검토 상태로 되돌린다.
- **내 정보 복원:** 병원 발행 식별정보는 읽기 전용으로 표시한다. 가상 주소·연락처는 빈 값에서 시작하고, 편집 → 확인 모달 → 로컬 저장 → 새로고침 복원으로 동작한다. `patient/storage.js`가 환자·입원건별 저장키, 형식 검증, 저장 실패 및 다른 탭의 변경 비교를 담당한다. 고정 시연 인물의 개인정보는 복사하지 않는다.
- **모의 기관 요청:** 저장한 변경에 동의한 뒤 `LOCAL_ONLY` 요청 기록을 남긴다. 실제 기관 전송·접수 완료로 표시하지 않는다. 편집 및 미저장 상태, 이미 기록된 같은 변경의 중복 요청을 막는다. 동의 상태는 모달 내 글자 크기를 바꿔도 유지한다.
- **이해 확인 복원:** 승인된 항목 원문을 보면서 ‘읽고 이해했어요 / 설명이 더 필요해요’를 선택·저장한다. 발행 ID·항목별 로컬 기록이며 새 버전에는 이전 확인을 승계하지 않는다. 의학적 정답을 만들거나 치료 수행·임상 이해도·의료진 전송으로 해석하지 않는다. 승인된 문항이 없는 상황에 맞춘 선택 참여 방식이다.
- **이동·접근성:** 통합 홈, 화면 내 홈/이전/다음, 사이드바, 모바일 4개 탭(내 정보 포함), 카드 상세, 전체 계획, 큰 글자, 도움 검색/상세, 현재 발행 안내 인쇄를 연결했다. 화면/선택 항목/가상 접속은 환자·입원건별 sessionStorage로 복원하며 새로고침 후 이전/다음은 안전하게 비활성화한다. 모달의 Tab/Shift+Tab 순환, Escape 닫기, 호출 버튼 포커스 복귀를 구현했다.
- **철회 후 복구:** 이력을 지우지 않고 ‘철회 후 새 버전 작성’ → 재검토 → 신규 승인·발행으로 복구한다. 철회된 원본은 REVOKED로 남고 새 발행 ID/버전을 사용한다. 정상 개정 중에는 이전 유효 발행본을 유지한다.

## 잔여 위험·외부 의존성 및 준비 상태

- **localStorage/IndexedDB는 인증·접근통제·암호학적 승인 증명이 아니다.** 같은 origin의 다른 스크립트나 사용자는 합성 저장소를 직접 변경할 수 있다. 운영형은 서버의 환자/입원건 권한, 발행·철회 트랜잭션, 파일 권한이 필요하다.
- A3의 비교 후 localStorage 쓰기는 서버 수준 원자적 동시성을 제공하지 않는다. PDF 비동기 준비 전후 및 개인 입력 저장 시 순차 충돌은 감지한다.
- PDF 바이트 저장과 발행 저장은 서로 다른 브라우저 저장소다. 파일을 먼저 저장하고 유효한 영속 발행본을 통해서만 읽는다. 중간 실패 시 노출되지 않는 미참조 파일이 남을 수 있다. 용량 실패는 발행을 차단하며 자동 정리/보관 정책은 후속 과제다.
- 이미 다운로드/새 창으로 내보낸 PDF를 철회 후 회수할 수 없다. 앱 내부 모달·링크·URL은 철회/신버전 때 제거한다. PDF의 의학적 내용·문서 안의 버전 의미를 자동 판정하지 않으며 재검토는 합성 의료진 절차다.
- 이전 래퍼 없는 역사적 합성 발행본은 자동 승격하지 않는다. 이전 3a572fd의 유효 래퍼/승인 기록은 유지하지만, 당시에 바이트를 제공하지 않은 문서는 새 검토·발행을 통해 제공해야 한다.
- 프로필·확인·요청은 브라우저의 로컬 합성 기록이다. 타 기기 동기화·기관 송수신·보호자 인증/공유는 구현하지 않았다. 일반 A3 문구/원천자료 편집 전체의 트랜잭션 전환은 이번 범위가 아니며, 주요 발행/승인/평가 전환의 기존 롤백은 보존한다.
- **합성 MVP 코드 검토 가능. 병합·배포 준비 상태: NOT READY** — Draft 검토와 별도 배포 승인이 필요하며 PR Draft 플래그/본문 재검증은 API 차단으로 미확인이다. 병합·배포·gh-pages 반영을 수행하지 않았다.
