## 변경 범위

1. `shared/publication.js`: A3의 **단일 영속화된 원본 저장키**를 읽어 발행 기록을 투영한다. `schemaVersion=1`, 환자 ID, 입원건 ID, 발행/평가 ID, 승인/발행 시점 및 상태를 검증한다. 공개 필드만 담는 `PatientPublication` allowlist를 생성하며 원천 평가, 내부 메모, 검토자, 감사 로그, 자료 해시, 첨부 바이트를 복사하지 않는다.
2. `a3/app.js`: 새 발행 시 입원건·평가 ID·승인시점을 `publications[]` 래퍼에 기록한다. **저장 성공한 발행본만** B에서 조회한다. 저장 실패 시 원래 A3 롤백 로직을 유지한다. 기존 내부 미리보기 옆에 `환자용 B 열기` 버튼을 추가한다. 실습 모드에서는 이 이동을 차단한다.
3. `patient/index.html`, `patient/styles.css`, `patient/app.js`, `patient/connected.css`: 원본 B v1.3의 HTML 셸과 스타일시트를 재사용한다. 독립 B 데이터 `published: true`는 읽거나 공개 근거로 이용하지 않는다. 환자/입원건 URL을 명시적으로 바인딩하고, A3의 현재 유효한 `PUBLISHED`만 홈·상세·전체·일정·도움 화면에 동적 표시한다. 홈·이전·다음(탭 내부 방문 이력)과 큰 글자를 지원한다.
4. 문서·진료 일정·복약 내용은 발행된 **문자열만** 표시한다. B v1.3 독립 시연의 이정희 기본정보, 10월 27일 외래, 보행 PDF, 기본 교육문구, 복약/퀴즈를 승인 자료로 재사용하지 않는다. 실제 PDF 링크/바이트가 없어 **문서명 + 기관 확인 필요**만 표시한다. HTML 특수문자는 이스케이프한다.
5. `shared/publication.test.js`와 `tests/patient_http.py`를 추가했다. 원본 A2 엔진, A3 구조/평가 규칙, B PR #2·원본 파일, 기존 PR·`main`·`gh-pages`는 수정하지 않는다.

## 재현 순서

저장소 루트에서 `python3 -m http.server 5500` 후:

1. `http://localhost:5500/prototypes/integrated-v10/a3/index.html?screen=plan&patient=SYN-002` 접속.
2. SYN-002 자료 검토 → 검토 요청 → 승인자 선택 → 승인 → **발행**.
3. `환자용 B 열기` → `CARE2026` 체험 코드 입력 → 발행된 같은 환자·입원건 v1.0 확인.
4. A3로 돌아가 개정 시작: B에는 구버전 유지. 새 계획 재검토·승인·발행: B에 신버전 표시. A3 철회: B 숨김.
5. `cd prototypes/integrated-v10 && npm test`; `python3 tests/patient_http.py`; `python3 tests/unified_http.py`; `python3 tests/phase1_http.py`; 실제 크로미움 버튼 조작과 폭별 시각 확인.

## 설계상 잔여 위험

- **같은 origin의 localStorage는 보안 경계가 아니다.** B의 코드가 브라우저 저장소 전체에 접근할 수 있으므로, allowlist는 UI 출력/시연 범위의 제어일 뿐 실환자 정보의 안전한 전송/접근 제어가 아니다. 누구나 로컬 합성 데이터를 변형할 수 있으며 승인 진위를 암호학적으로 보장하지 않는다. 운영형은 서버 측 환자·입원건 권한 검사, 서명 또는 권위 있는 발행 레코드, 철회/버전 원자화, 파일 권한 보관이 별도로 필요하다.
- A3의 이전 발행 기록 중 래퍼 ID가 없는 역사적 합성 데이터는 B에 표시되지 않는다. 침묵 속 자료 승격보다 오노출을 막는 보수적 선택이다.
- 개별 환자·보호자의 정식 로그인, 상호기기 동기화, 실제 PDF 원본, 실제 의료지시/예약, 장애 복구, Safari/Firefox/실기기/스크린리더 검증은 구현 또는 실행 범위 밖이다.
- **통합용 B에서 독립 B v1.3의 프로필 수정·확인문제·교육 PDF 기능은 안전상 재사용하지 않고 별도 구현을 보류**했다. 원본 PR #2와 현재 배포된 독립 B 경로는 변경되지 않는다. 신규 통합 경로는 공개 승인이 없는 기능성 예시보다 오노출 차단을 우선한다.
- 사용자 확인 전 배포하지 않는다.
