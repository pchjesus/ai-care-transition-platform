# A1→A3→B 실제 화면 스포트라이트 튜토리얼 v1.0 — Codex 구현 계약
작성: 2026-10-22 · 범위: 합성 데이터 기반 병원용 워크벤치 및 독립 환자용 예시. 연구·임상 검증 완료를 의미하지 않음.

## 1. 사용자 제공 HandyDocs 캡처에서 직접 확인한 패턴
- 2/10: 실제 서비스 화면에 반투명 어두운 오버레이를 깔고, 우측 패널의 행동 버튼을 선명하게 강조. 대상 근처에 단계 수/제목/짧은 설명을 가진 흰색 말풍선과 이전·다음 버튼. 우상단에는 튜토리얼 건너뛰기.
- 3/10: 실제 입력 양식 중 중요한 입력영역만 넓은 사각형으로 밝게 남기고 주변을 어둡게 가림. 말풍선이 대상 아래에 붙고 작은 삼각형 꼬리로 대상과 연결됨.
- 4/10: 작업 진행 화면/진행률 요소를 강조한 뒤 말풍선으로 설명. 스크롤이 있는 긴 페이지에서도 진행 상태가 유지됨.
- 별도 캡처: 우하단 질문/도움말 UI를 제공. **이 사례는 AI 챗봇 구현을 필수로 요구하지 않는다.**
- 위는 캡처에서 볼 수 있는 동작·배치의 관찰이며 실제 키보드/모바일/자동 포커스 구현은 검증되지 않음.
- **참조하는 것은 인터랙션 원리다.** HandyDocs의 브랜드/색상/텍스트/아이콘·고유 UI를 복제하지 않고 기존 케어브릿지랩 포레스트 그린 디자인 시스템에 맞춘다.

## 2. 현재 시스템의 확인된 출발점
- 병원용 A1/A2/A3/학습 탭은 `prototypes/integrated-v10/a3/index.html`의 통합 워크벤치에서 이동하며 `a3/app.js`가 화면을 렌더링함.
- 현재 `a3/tutorial-tour.js`/`tutorial-tour.css`는 6단계 **독립 모달 + 정적 미니 화면**. 사용자 요청에 필요한 실제 화면 위치 강조·스크롤 추적 경험은 제공하지 못함.
- 학습 탭 L01/L04의 `data-learn-guided-tour` 진입은 유지. 기존 케이스 실습 `data-study-start`, `mode=study` 별도 저장도 보존.
- 이전 환자용 **독립 B v1.3**는 공개 사이트 `patient/index.html`. A3 발행본을 읽는 **연동 B**는 `prototypes/integrated-v10/patient/index.html`. 두 콘텐츠를 혼동하거나 발행 상태를 날조하면 안 됨.
- 환자 이름은 합성 사례 레지스트리에서 환자·입원건 검증 후 표시. SYN-001 이정희 등의 기존 매핑·승인 공개 규칙을 유지함.

## 3. 목표 UX — 짧게 둘러보기와 직접 조작을 구분
### A. 읽기 중심 '화면 둘러보기'(우선 구현)
- 학습 L01/L04에서 `화면 따라 체험하기` 선택 → **기존 A1/A2/A3 실제 렌더된 화면 위에 안내 오버레이**. 가상의 전체 화면 미니어처를 최종 UI로 남기지 말 것.
- 현재 화면에서 밝게 남길 실제 요소를 자동 스크롤해 표시. 강조용 링/테두리, 반투명 주변 마스크, 말풍선 꼬리, 이전·다음·전체 단계 진행률·건너뛰기(종료까지)·닫기 제공.
- 오버레이 진행 중에는 실제 계획 수정·저장·역할 전환·승인·발행·철회 버튼에 이벤트를 전달하지 않는다. 대상 강조는 ‘안내’이며 실제 실행이 아님을 명확히 표시.
- 기존 `go()`/렌더 함수의 필요한 읽기 전용 화면 전환 API만 재사용/얇게 노출. 표시 때문에 환자 ID, normal/study localStorage, 발행/개정 이력, 역할 및 평가값이 변하지 않도록 할 것. 화면/활성 탭/스크롤/포커스는 가능한 한 이전 상태로 복원.
- 전체 내용을 짧게 유지: 한 단계 제목 한 줄 + 설명 1~3문장. 언제든 건너뛰기/닫기.
### B. '업무 직접 실습'(기존 기능 보존)
- 실제 버튼 조작 실습은 기존 `mode=study`의 **합성 사본**에서만 수행. 사용자 요청이 없는데 일반 발행 저장소에 실습 데이터를 남기는 자동 시나리오를 만들지 말 것.
- 간호사/약사/의사 분야별 검토와 최종 승인자 전체 발행 권한의 차이를 정확히 설명. 튜토리얼의 다음 버튼이 실제 검토·승인·발행을 호출하면 안 됨.
- 이후 고급 조작형 코스는 확장 가능하게 설계하되, 첫 배포에 복잡한 단계 강제/자동 클릭/새 임상 데이터 생성은 불필요.

## 4. 추천 10단계(선택자는 최신 DOM 확인 후 안정적인 data-tour-anchor로 지정)
| 단계 | 실제 UI 대상·화면 | 한 줄 학습 목표 |
|---|---|---|
| 1 | A1 환자 목록 / A1 탐색 | 환자 선택을 먼저 알아요 |
| 2 | A1 합성 환자 카드/환자·입원건 정보 | 이름과 입원건이 맞는지 확인해요 |
| 3 | A2 6영역 탐색(3패널 레일/반응형 가로 배치) | 평가 영역을 선택해요 |
| 4 | A2 중앙 평가 입력 + 우측 판단 결과 | 입력값과 업무 검토 우선도를 구분해요 |
| 5 | A3 계획 편집(첫 항목 또는 외래 일정) | 환자에게 전달할 말을 작성해요 |
| 6 | A3 원천 근거 카드/기록 추가 | 확인된 자료를 여러 개 연결할 수 있어요 |
| 7 | A3 담당 역할과 직종 검토 | 간호사·약사·의사의 역할을 알아요 |
| 8 | A3 검토 요청/최종 승인/발행 안내 또는 액션 영역 | 승인과 발행은 별개예요 |
| 9 | A3 환자용 미리보기(초안/발행본 명시) | 실제 환자 공개 전 내용을 확인해요 |
| 10 | 튜토리얼 종료 안내/독립 B v1.3 진입 | 실제 예시 환자 화면을 직접 체험해요 |

- 어떤 환자의 발행 상태 때문에 버튼이 숨겨졌다면 `#workflow-guidance`나 하단 액션 컨테이너 등 **안전한 대체 강조 대상**을 선택. 없는 버튼을 억지로 클릭하거나 승인 상태를 만들어내지 말 것.
- 단계 10의 **기본 CTA는 원본 독립 B v1.3으로 이동**. 'A3에서 발행된 연동 B 보기'는 실제 유효한 발행본을 가진 환자에 한하여 별도 선택지로 표시; 미발행이면 승인 계획처럼 표시 금지.
- 현재 6단계 튜토리얼을 10단계로 교체하되, 단계 데이터는 선언형 배열로 재사용/테스트 가능하게 유지.

## 5. 오버레이 엔지니어링
- 현재의 중앙 `<dialog>` 안 미니 UI만 강조하는 방식이 아니라, **실제 앱 요소의 bounding box를 추적하는 spotlight**가 목표. 최소 4면 마스크 또는 동등한 접근성 있는 cutout 방식으로 실제 UI 위치가 보이게 할 것.
- 단계 진입 시 대상 `scrollIntoView`; 화면 리사이즈/스크롤/대상 DOM 재렌더 시 위치를 동기화. 대상이 없거나 hidden이면 인접한 설명 대상이나 중앙 안내로 안전하게 fallback.
- 말풍선은 대상 주변에서 위/아래/좌/우의 가용 공간을 보고 배치. 뷰포트 밖/키보드·모바일 버튼과 겹치거나 설명이 잘리는 문제를 방지. 작은 삼각형 방향은 실제 대상 쪽.
- 툴팁·이전/다음/닫기 모두 키보드 접근 가능. Escape 닫기, focus trap 혹은 적절한 동등 처리, 열었던 버튼으로 포커스 복귀, 단계 설명 스크린리더 발표, 44px 이상 클릭 대상, 읽기 쉬운 글자 크기 및 대비.
- 390/768/1024/1440 CSS px, 큰 글자, 200% 확대, `prefers-reduced-motion` 확인. 애니메이션은 짧게, 화살표가 시선을 방해하지 않도록 동작 축소 옵션 존중.
- 챗봇을 추가 구현하지 않는다. 도움말은 기존 학습 탭/빠른 도움말을 재활용하고 현재 튜토리얼 완성에 집중.

## 6. 기존 UX 및 의료 안전 보존
- 현재 정상 A1/A2/A3/B/PDF/자료 연결/철회 요청/개정/승인·발행 기능 삭제 금지. 디자인 전체 개편·타사 UI 복제 금지.
- 튜토리얼 전/후 일반 저장소와 학습 저장소, 발행 스냅샷·버전·승인 해시 비교하여 **읽기형 투어로 업무 데이터가 변하지 않음**을 확인.
- 승인·발행된 합성 자료와 원본 독립 B 예시는 다른 데이터 출처라는 표기를 유지.
- 실제 환자정보·실제 예약·투약·임상적 효능을 임의 생성하지 말 것.
- 앱 탐색/역할 권한 UI 변경이 필요한 경우 기존 안전 게이트와 충돌 여부 검증.

## 7. Codex 검증 기준 및 적용
1. 현재 원격 main HEAD 확인. AGENTS.md가 있으면 해당 범위만 읽고 이 문서, `a3/tutorial-tour.{js,css}`, `a3/app.js`, `a3/index.html`, 관련 테스트만 우선 조회. 원본 B는 보존 확인에 필요한 범위만.
2. 구현 후 `cd prototypes/integrated-v10 && npm test` 및 브라우저 E2E (`tests/unified_http.py`, `tests/patient_http.py`, `tests/phase1_http.py`)를 환경이 허용하는 범위에서 **실제 실행**. 새 튜토리얼 클릭/스크롤/포커스 및 data unchanged 전용 Playwright 테스트를 추가.
3. 390/768/1024/1440px 시각적 증거 스크린샷 생성 및 offscreen/overlay 겹침 검토. 키보드와 닫기/재진입, 단계 내 임의 스크롤, 대상 누락을 테스트.
4. 기능 결함 발견 시 파일 영향 범위를 좁혀 수정하고 필요한 회귀를 재실행. 불필요한 전체 저장소 탐색/중복 분석/무관 리팩터링 생략하되 **구현·실제 테스트는 생략하지 말 것**.
5. 사용자 운영 정책: 안전한 변경이 검증되면 `main`에 푸시, 확인된 정적 산출물만 `gh-pages`에 별도 반영. 기존 PR #1~#4나 기존 이력은 건드리지 말 것. 원격 HEAD 변경 시 무리한 force push 없이 재확인.
6. 보고: 변경 기능, 테스트 PASS/FAIL/NOT RUN, 실브라우저 스크린샷 확인, 남은 위험, main/pages SHA와 시연 링크를 간단히 기록. 실제 못 돌린 테스트를 PASS라고 보고하지 않는다.

## 8. 결과물
- ‘화면 따라 체험하기’를 눌렀을 때 실제 병원 워크벤치 A1/A2/A3의 주요 부분만 조명되는 사용 가능한 투어
- 언제든 종료/건너뛰기, 마지막 기존 독립 환자 B 진입
- 일반 임상 시연 저장 상태 불변, 기존 별도 케이스 실습 보존
- 필요 범위의 자동 검증 및 짧은 개발 기록

**참조 캡처와의 차이:** 본 요구는 화면에서 확인할 수 있는 상호작용 패턴을 케어브릿지랩에 맞게 재구성한 것이며, HandyDocs의 실제 구현 코드·접근성 준수·튜토리얼 저장 방식은 알 수 없다.
