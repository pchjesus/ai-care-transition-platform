## 1. 범위와 결정

**P0 성공 시연:** A1 가상 환자 선택 → **원본 A2 v0.5의 UI를 보존한 평가** → A3 검토·승인·발행 → **실제 환자용 B v1.3의 UI를 보존한 동적 안내** → 개정/철회 반영.

**구현 전략:** 독립 폴더 `prototypes/integrated-v10/`에서 두 Draft 후보와 A2 원본을 **기준 SHA로 가져와 별도 작업 사본**으로 통합한다. 기존 `prototypes/hospital-a2/`, `hospital-a3/`, `hospital-a3-v04/`(원격 후보), `patient-v12/`, `patient-v13/`(원격 후보) 원본 변경 금지. 개발 브랜치에서 필요한 모듈만 복사/공유하고 HTML/CSS 레이아웃을 전면 재작성하지 않는다.

A3 자체의 A2 모의 화면은 후속 참고로 유지하되, **통합 모드의 환자 평가 원천은 실제 A2 v0.5 화면과 엔진 1개**로 정한다. A2→A3 인계를 버튼/호스트 어댑터로 명시적으로 수행한다. 병원용 화면을 서로 다른 데이터 원천으로 동시에 수정할 수 없게 한다. A1 목록은 범위를 줄이기 위해 현재 합성 사례 선택 UI를 활용한다.

**초기 통합 환자:** SYN-002 정상 완료 경로; SYN-001 검토·누락 보완; SYN-003 결측·상충 차단. 이후 SYN-004 버전 실습은 별도 확장. 실데이터·EMR·Firebase·정식 로그인·기관 전송·실제 AI 의사결정은 이번 범위 밖.

## 2. 통합 데이터 계약 (P0)

기존 도메인 구조를 교체하지 않고 **버전 관리되는 어댑터**를 새로 만든다.

### A2 → A3: AssessmentHandoff V1

```js
{
  schemaVersion: 1,
  isSynthetic: true,
  patientId: "SYN-002",
  encounterId: "ENC-SYN-002-DEMO",
  assessmentId: "AS-SYN-002-<revision>",
  ruleVersion: "a2-v05",
  capturedAt: "<ISO-8601>",
  values: { medical: {}, nursing: {}, medication: {}, function: {}, social: {}, continuity: {} },
  // domainResults = A2 엔진 검증 산출값. 현 A2의 tier/provisionalTier는
  // A3의 grade/provisionalGrade와 이름이 다르므로 명시적 매핑·일치 검증 필요.
  domainResults: []
}
```

- 인계 대상은 **선택된 합성 환자 + 고정된 가상 입원건**. 화면에 표시된 이름으로 식별 금지.
- 입력 항목 ID·유효 옵션, 필수항목 누락/상충, 계산 재현성을 검증. `domainResults`는 입력에서 재계산하여 위·변조/불일치 시 거부.
- 인계는 사용자의 명시적 동작으로만 수행. 이미 승인된 미발행 초안은 승인 무효화·재검토, 발행 중인 계획은 **개정 시작 후** 인계. 원래 발행본은 새 승인·발행 전까지 유지.
- A3 자체 평가 기준과 A2 엔진의 차이가 있으면 조용히 같은 등급으로 간주하지 말고 테스트와 명시적 매핑으로 해결. 임상 점수 아닌 자체 업무 검토 우선도.

### A3 → B: PatientPublication V1

```js
{
  schemaVersion: 1,
  isSynthetic: true,
  patientId: "SYN-002",
  encounterId: "ENC-SYN-002-DEMO",
  publicationId: "PUB-...",
  planVersion: "1.0",
  assessmentId: "AS-SYN-002-...",
  approvedAt: "<ISO-8601>",
  issuedAt: "<ISO-8601>",
  status: "PUBLISHED", // 철회 이벤트는 "REVOKED", 구버전은 "SUPERSEDED"
  items: [
    { id: "today", title: "오늘 해야 할 일", section: "today", text: "승인된 내용" }
  ],
  documents: [ {id: "doc1", name: "시연용 승인 자료"} ]
}
```

- 이 객체는 A3의 **현재 유효한 발행 기록**에서만 생성하는 **환자 공개용 allowlist projection**이다. `draft`, `assessment` 원자료, 검토 이슈, 내부 메모, 원천기록, audit, 실제 파일 바이너리·보호자 미승인 정보는 복사 금지.
- `PUBLISHED`만 환자에게 상세 안내 노출 가능. **APPROVED(발행 전), REVIEW_REQUESTED, DRAFT, REVOKED, 미수신/손상된 값은 노출 차단**. 버전·환자·입원건·승인시점 일치 필수.
- 기존 `publishedPayload`는 `patientId, planVersion, approvedAt, items, documents, issuedAt`만 제공. 위 객체의 `encounterId, publicationId, assessmentId, status`는 검증된 **A3 record/publication wrapper**에서 보완해야 한다. 임의로 만들어 넣거나 B의 기존 `published:true`를 사용하지 않는다.
- **환자 앱의 통합 모드**에선 `createDemoRepository().loadPlan()`의 기본 published 상태를 공개 근거로 사용 금지. 통합 전용 저장 키/adapter로 따로 읽고, 데이터가 없거나 오류면 **'아직 발행된 안내 없음'**. 독립 `patient-v13/` 단독 데모 동작은 유지.
- 기존 B의 하드코딩된 '퇴원 3일째', 10.27 예약, 이정희 성명, 보행 PDF, 3개 과제·복약 메시지가 **다른 환자나 다른 버전의 의료진 승인 정보인 것처럼 표시되면 안 됨**. 통합 모드에선 A3 스냅샷 텍스트를 알맞은 카드에 연결하거나 안전하게 카드/일정/첨부를 숨긴다. 승인된 정확한 일시·약물 용량·개인별 응급기준이 없으면 추론해서 생성하지 않는다.
- `A3.documents`는 **파일 이름 메타데이터만** 환자 공개 projection에 있다. B에 실제 PDF bytes/링크가 있다고 가정하지 말고 '기관 확인 필요' 등으로 표시; 무관한 기존 PDF와 연결 금지. PDF 원본 제공은 별도 보안·영구저장 설계 후 확장.
- 개인별 보호자 접근은 이번 단계에서 가상 데모 권한 이상으로 주장하지 않는다.

## 3. 전달·저장·버전 정책

- 로컬 HTTP 동일 origin 합성 데이터 전용. 구현 편의에 따라 **동일 origin 통합용 localStorage 키** 또는 명시적 호스트 브리지 사용 가능. 추천 키 `care-transition-integrated-v10-synthetic-only` (기존 A3/B v1.3 키 덮어쓰기 금지).
- 공유 키는 검증된 `schemaVersion`, `patientId`, `encounterId`, 현재 발행본 + 철회 정보 + monotonic revision을 저장. 오염·파싱 오류·저장 불가·버전 역행·타 환자 전환은 **fail-closed**.
- 모든 발행·개정·철회는 A3 쪽 단일 동작에서 발생. B의 시연 개발자 도구는 이 데이터 소스를 조작할 수 없음. 통합 모드와 독립 데모 상태 섞지 않기.
- 수정 중인 새 버전은 환자에게 보이지 않으며, 기존 발행본이 유효하면 **기존 발행본을 유지**. 발행 시 구버전 SUPERSEDED, 철회 시 현재 버전 REVOKED 및 B 즉시 차단. 새로고침·다른 탭에서도 일관.
- 같은 이름/환자라도 입원건이 다르면 절대 혼합하지 않는다. 다른 탭의 동시 수정은 저장 충돌 감지 후 중지·재로드 안내; 브라우저 로컬 저장은 실제 인증/원자적 서버 트랜잭션이 아니다.
- 역호환: 단독 A2 v0.5, A3 v0.3 및 v0.4 후보, B v1.2 및 v1.3 원본의 저장 키·스타일·기능 그대로 보존. 새 통합은 독립 경로 및 키에만 기록.

## 5. 개발 순서·허용 변경

1. **수정 전 읽기:** 이 계약 → 기존 PR #1/#2의 각 `README.md` → 기존 A2 `data.js/engine.js/app.js` → A3 `workflow.js/storage.js` → B `storage.js/app.js` 중 연결에 필요한 영역만. 저장소 전체·테스트 산출물 이미지·과거 리포트 일괄 로드 금지.
2. **P0:** 통합 복사본/시작 페이지, 정규화·검증 어댑터, A2→A3 명시적 인계, A3→B allowlist 전달, 공개/철회 반영, 원본 보존.
3. **P1:** 병원/환자 이동 링크, 가상 환자 레이블/연도 및 접근성 개선 *필요한 최소 범위만*. 기존 디자인 재개발 금지.
4. **검증:** 저비용 Node 도메인 검사 → 관련 HTTP 실제 UI/스토리지 → 기존 테스트 중 영향 범위만 → 화면 비교/시연. 오류 있을 때만 확장 검사.
5. 독립 **개발 브랜치**(예: `codex/integrated-mvp-v10`) 생성, 원본·main·기존 PR 수정/병합 금지. 제출은 Draft PR + 검증 보고서와 재현법. 성공이라고 선포하기 전에 실제 수행한 테스트를 공개.

**중단·보고할 결정:** A2 UI 원본 보존과 안전한 인계의 양립 불가, 승인 스냅샷 동적 표현 불가, 시연과 진짜 데이터 연동이 혼동될 위험, 저장 격리 불가라면 억지 구현하지 말고 최소 대안·위험과 함께 보고한다.

## 6. 완료 기준

- 한 명의 가상 환자에 대해 **A2 원본 UI → A3 승인·발행 → B 동적 본문**이 실제 UI 조작으로 이어진다.
- 철회·개정·환자 혼동·미발행·누락·저장 장애의 잘못된 공개를 차단한다.
- 모든 원본 폴더, PR #1/#2, 사업계획서 문서, 배포를 변경하지 않는다.
- README의 실행법, 신규·회귀 테스트 수치, PASS/FAIL/NOT RUN, 알려진 한계가 서로 일치한다.
