# R13 택시 연동 준비형 화면 — 입력·선택·미리보기 설계 (2026-10-23)

현재: **MVP 화면 시연**, 실제 택시 호출·결제·외부 병원/이동지원기관 알림 미구현.

## 사용 흐름

1. ‘일반 택시’ 또는 ‘이동에 도움 필요’를 선택한다.
2. 1단계: 가상 출발 장소 메모, 방문할 병원 목적지를 확인한다. A3가 의료진 검토 후 실제 **발행**한 목적지만 선택 목록에 표시된다. 주소가 없으면 미확인 표시. 독립형 B에서 직접 입력하는 목적지 메모는 확인되지 않은 **가상 예시**로 분리된다.
3. 2단계: **차량에 가지고 탈 것**(접이식 휠체어/전동 휠체어/워커·보행기/지팡이·목발/없음), **병원에 내린 뒤 필요한 도움**(출입구 안내/부축 문의/병원 휠체어 대여 문의/보호자 합류/없음), 동행 여부를 구분해서 체크한다.
4. 3단계: 선택 내용을 화면에서 확인하고 이전 단계로 수정한다. ‘카카오 T 연결 · 준비 중’은 비활성화되어 있으며 외부 서비스를 열거나 실제 예약을 만들지 않는다.

## 확장 계약(현재 연동 보류)

- 카카오 T 공식 제휴·딥링크·사업자 API 지원 범위와 정식 계약을 확인하기 전에는 임의 호출 URL, 예약 가능 시간, 요금, 배차 성공 상태를 생성하지 않는다.
- 향후 카카오 T와 실제 연동할 수 있더라도 **출발지·목적지**, **개인 이동보조기구 정보**, **병원에 필요한 지원 요청**은 서로 다른 전달 목적과 수신자를 가질 수 있다. 각 항목별 동의 및 외부 서비스의 지원 가능 여부를 별도로 확인한다.
- 현재 택시 입력은 DOM 및 JS 메모리에만 존재한다. 로컬 저장소, 합성 환자 의료정보 저장소 또는 외부 전송에 추가하지 않는다. 실제 집 주소·전화번호·건강정보 입력을 요청하지 않는다.
- 의료적 이송이 필요할 때 일반 택시의 적합성을 앱이 판단하지 않는다. 장애·교통약자 지원 가능 여부도 확인되지 않은 것으로 표시한다.

## 검증

단위/브라우저 및 기존 경로 회귀는 GitHub Actions 실행 결과에 따라 PASS/FAIL 분리 기록. 외부 카카오 T 호출·실제 환자 과업·실기기 모바일/스크린리더 검증은 NOT RUN.
