## 구분 기준
- **A 보완·도입**: 기존 의료진/환자 업무와 직결하며 현재 UI 안에 조용히 이식할 가치가 있다.
- **B 재설계 후 선택**: 원본 기능은 가치 있지만 상호작용, 업무흐름, 역할, 데이터 게이트를 먼저 확인해야 한다.
- **C 별도 유지 / 이식 제외**: 실제 업무 공간에 불필요하거나 중복, 학습/검증 전용이며 원본을 보존하면 충분하다.

## 후속 실행 시점

환자 B의 UI/UX v1.6 후보를 검토·확정한 뒤 다음 순서로 진행한다.

1. 의료진 UI v0.7과 환자 B v1.6 후보의 실제 화면, 자료 흐름, 승인/발행/개정/철회 데이터 계약 검토.
2. 우선 **A** 기능만 변경 영향 판단 후 현재 UI에 최소 이식; **B**는 사용성·업무 필요성이 확인된 경우에만 선택적으로 적용.
3. A1→A2→A3→B, PDF 원본/인쇄, 확정 일정·목적지, 부정확한 상태 차단, 환자·입원건 격리, 동시 수정, 버전·철회 및 모바일/PC 회귀 검증.
4. 기존 UI 잠정 확정 부분, 원본 레거시 기능, `main`/`gh-pages` 운영 릴리즈를 구분하여 보존. 검증되지 않은 기능을 완료로 보고하지 않음.

**현재 상태:** 이 문서는 의사결정과 이월 목록만 기록한다. 위 기능의 재구현, 테스트 실행, 릴리즈는 수행하지 않았다.
