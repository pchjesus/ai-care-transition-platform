# MVP Product Requirements Draft v0.1

- 상태: **DRAFT / 미승인 / 미구현** (2026-10-19)
- 최초 개발 목적: 병원 퇴원연계 업무 자동화·검토·연계 경험에 대한 사용성 및 제품 가치 검증.
- 임상 제품 또는 의료기기 성능을 입증하는 산출물이 아니다.
- 작업 착수 전 [사업모델 초안](./BUSINESS_MODEL_DRAFT_v0.5.md)과 [연구·근거 계획](./RESEARCH_AND_EVIDENCE_PLAN_v0.1.md)을 함께 검토한다.

## 1. 제품 경계

가상 환자, 가상 진료기록, 가상 제공기관, 모의 의뢰·모의 승인만 사용한다.
실제 병원·지자체·보험 시스템 연동, 실제 환자정보, 실제 의료 판단·진단·처방·신청·의뢰 전송은 구현하지 않는다.
규칙기반 분류는 학습된 AI 예측모델과 분명하게 구분한다.

## 2. 최초 사용자 및 테스트 페르소나

- 의료진/퇴원연계 담당자: 가장 중요한 사용 흐름(A1).
- 의료진 상담자: 환자 1명 분석 및 설명(A2).
- 제공기관 담당자: 모의 의뢰 접수 및 회신(C).
- 환자·권한 있는 보호자: 승인된 내용 열람(B).
- 관리자: 처리량·업무시간·상태 지표(D).

MVP에서 역할 전환은 **시연 기능**이며 실제 인증·접근 통제를 제공한다고 주장하지 않는다.

## 3. 대표 가상 사례

1. 독거 고령 복합만성질환자: 약료·사회지원 등 다영역 검토.
2. 뇌졸중 후 기능 제한자: ADL/이동 등 기능 평가 및 연계.
3. 돌봄 환경 정보 누락자: 임의로 정상·고위험 판정하지 않고 보완 요청.
4. 대조 사례: 추가 연계 필요도가 상대적으로 낮은 환자.

모든 사례는 완전히 허구이며 실제 개인·병원 정보와 무관하도록 작성한다.

## 4. 기능 범위

### P0 — 작동하는 최소 업무 흐름

| ID | 기능 | 관찰 가능한 수용 기준 |
|---|---|---|
| P0-01 | 퇴원 예정 환자 목록·검색·필터 | 환자별 ID·상태·검토 이유가 혼합되지 않는다 |
| P0-02 | 설명 가능한 규칙 평가 | 결과마다 규칙 버전·출처·근거가 표시된다 |
| P0-03 | 누락·불확실 정보 표현 | 자료 없음이 0점 또는 이상 없음으로 변환되지 않는다 |
| P0-04 | 의료진 검토·수정·승인·보류·반려 | 작성자·시각·이력이 남고 비인가 상태 전환이 차단된다 |
| P0-05 | 서비스 후보·모의 의뢰 | 승인 전 전송 불가, 중복 전송 방지 |
| P0-06 | 가상 기관 수락·거절·결과 회신 | 의뢰 수락과 실제 제공 완료가 혼동되지 않는다 |
| P0-07 | 환자 분석·상담 전환(A2) | 내부 정보·승인 전 결과가 상담용에 노출되지 않는다 |
| P0-08 | 환자·보호자 모바일 보기(B) | 공개 승인된 돌봄계획·일정·진행상태만 표시 |
| P0-09 | 관리자 기본 통계(D) | 가상 작업 이벤트에서 지표가 계산되고 출처 표시 |
| P0-10 | 저장·복원·변경이력 | 새로고침·역할전환 후 데이터 일관성과 변경이력 유지 |

### P1/P2 — 후속 연구 후 확장

P1: 비정형 모의 기록의 LLM 요약/근거 추출, 기관별 서식 템플릿, 고급 보고서, 추가 사용자 테스트.
P2: 실제 인증·기관별 격리·서버/DB·EMR/FHIR 연계, 임상검증 AI, 실제 서비스 기관 연계. 별도 승인·법률 검토 후 수행.

## 5. A1 / A2 / B 디자인 우선순위

- **A1 Clinical Workbench (중심):** 고밀도 업무 대기열, 한 화면의 상태 파악, 안전한 빠른 처리.
- **A2 Patient Analysis & Consultation (중요):** 의학적·간호적·사회적 필요의 영역별 근거, 추세, 결측, 검토 상태; 설명용 보기로 즉시 전환.
- **B Patient/Caregiver Portal (필수):** 큰 조작 영역, 쉬운 표현, 일정 및 다음 행동, 디지털 취약 이용자를 위한 상담·인쇄 경로 검토.
- **C Referral Workspace:** 모의 전송·수락·거절·실제 제공과 미제공 결과 구분.
- **D Performance Dashboard:** 처리건수·소요시간·재작업·미해결 수치의 계산 정의 공개.

서로 다른 역할 화면이 같은 원본 데이터를 무조건 동일하게 노출하지 않는다. 환자 공개 뷰는 **별도 승인된 출판용 데이터 스냅샷**으로 구성한다.

## 6. 초기 평가 원칙

여섯 영역(의료, 간호, 약료, 기능/ADL, 사회환경, 돌봄 연속성)은 **제품 설계용 분류틀**이며 공식 판정척도가 아니다.
임상 위험 예측, 돌봄 필요도, 서비스 자격·적합성, 업무 우선순위, 의뢰 진행도를 각각 분리한다.
임의의 '종합위험도 85점' 같은 임상적으로 검증되지 않은 값은 표시하지 않는다.
AI 출력은 전문가 검토를 대체하지 않으며, 결측·모순·오류·근거 부족을 드러낸다.

## 7. 도메인 개체(제안)

Patient, Encounter, Assessment, AssessmentEvidence, AssessmentRuleVersion, Review, CareNeed, CarePlan, Service, ServiceProvider, Referral, ReferralResponse, PatientPublishedView, AuditEvent.

각 객체의 ID, 타임스탬프, 생성·수정자, 버전, 출처, 상태를 설계 단계에서 정의한다. 실환자 필드가 섞이지 않도록 mock namespace를 분리한다.

## 8. 상태 전환 계약(제안)

- 평가: DRAFT -> NEEDS_REVIEW -> APPROVED / ON_HOLD / REJECTED (수정 시 새 버전 기록).
- 의뢰: DRAFT -> APPROVED_FOR_SIMULATION -> MOCK_SENT -> RECEIVED -> ACCEPTED/DECLINED -> SERVICE_DONE/SERVICE_NOT_DONE.
- 의뢰 결과 재검토, 취소, 미응답 타임아웃, 중복 요청 처리는 별도 예외상태 설계가 필요하다.
- **승인되지 않은 의뢰는 MOCK_SENT로 전환할 수 없다.**
- **ACCEPTED와 SERVICE_DONE은 동일한 상태가 아니다.**
- 기존 승인 기록과 모의 의뢰는 새 규칙평가 실행 시 자동 덮어쓰지 않는다.
- 브라우저 저장은 시연 편의용일 뿐 보안·기밀성·다중 사용자 동시성 해결책이 아니다.

## 9. 구현 구조 (후보, 결정 전)

- HTML5 + CSS3 + Vanilla JavaScript(ES modules) 기반 역할별 화면으로 초기 구현. 기술 방향은 [TECH_ARCHITECTURE_DIRECTION_v0.1.md](./TECH_ARCHITECTURE_DIRECTION_v0.1.md) 참조. 향후 필요시 프레임워크 도입 검토.
- 평가 규칙, 워크플로 상태 전환, 표시/렌더링의 논리적 분리.
- 초기에는 mock data provider + 로컬 저장; 향후 승인 API adapter/서버로 교체 가능하게 설계.
- GitHub Pages는 공개 시연용 가상 데이터만 사용할 경우 별도 승인 후 활성화.
- B+ 개발 정책: 현재 main·계약·회귀 위험 확인 -> 설계·수용 기준 -> 작은 변경·검증 -> 사용자 확인 -> 문서 및 릴리스.
- 디자인 깎기 범용 디자인 지침은 참고하되 임상 워크플로·가독성·안전한 상태전환이 우선.

## 10. 테스트·성과 수집 계획

기능: 평가 근거, 결측, 수정/승인 이력, 잘못된 상태 전환 거부, 의뢰 중복 차단, 공개 범위, 저장/복원, 예외·반려 흐름.
사용성: 동일한 가상 업무의 기준 절차 vs MVP 수행시간, 오류, 사용자별 성공률, 환자 설명 이해도.
보안: 공개 데모에 실환자·실기관 계정·병원 내부 업무자료·비밀값이 없는지 점검.
경영: 병원별 처리량과 실제 시간 절감 검증 후 가격·원가 모델에 반영.

과거 논의의 '업무시간 20% 단축' 등 수치는 **목표 가설**이지 검증된 성능이 아니다.

## 11. 개발 게이트

- Gate 1: 고객 문제와 첫 업무 범위 검증.
- Gate 2: 임상·제도적 분류와 평가 근거 확인.
- Gate 3: 역할·데이터·업무 상태 계약 승인.
- Gate 4: 실제 개발·브라우저 테스트 및 사용자 검증.
- Gate 5: 발표용 데모 구성 및 사업적 가설·한계 명시.

**이 문서는 개발 지시나 의료 활용 허가가 아니며, 아직 구현 작업은 시작하지 않았다.**
