# R02 기존 시스템·경쟁 환경 비교 v0.1

- 날짜: 2026-10-20
- 상태: **데스크 리서치 완료(공개 설명자료 한정), 실제 제품 시연·현장 사용성·가격 조사 미완료**
- 목적: '새 플랫폼'의 기능 중복을 줄이고 국내 병원 구매가치를 구체화한다.
- 모든 제품 비교는 공개된 공식 설명에 한정한다. 공개 소개에 기재되지 않은 기능을 '부재'로 단정하지 않는다.

## 1. 경쟁 구도를 정의하는 방법

1. 직접 대체: 병원의 자체 EMR/퇴원연계 모듈, 국립중앙의료원 공공의료연계망, 국가 통합돌봄 정보체계.
2. 기능 인접: 의료 AI 조기경고·평가, 환자 돌봄 매칭 플랫폼.
3. 해외 선행 모델: Epic/Findhelp/Unite Us 등의 EHR 연계·양방향 결과 관리.
4. 실제 B2B 판매 가능성을 보여주는 참고: 병원용 의료 AI 업체의 상용 계약 사례. **퇴원연계 SW 시장 크기와 혼동 금지**.

## 3. 엄격한 차별화 가설

**금지 또는 보류:** 국내 최초, 기존 공공망이 양방향 의뢰를 제공/추진하지 않는다, 의료기관은 평가·모니터링 전산이 전혀 없다, 의료 AI 위험도 자체가 새롭다.

**검증 후보:**
1. 병원 기존 정보의 **반복 재입력 감소**: 출처 표시, 입력값 재사용, 가상 서식 채우기.
2. 누락/모순/사업별 필수 자료의 **제출 전 점검**.
3. 기관별 역할(선별·평가·검토·서식 책임자) 및 국가사업 종류를 **설정 가능한 워크플로**로 관리.
4. 의료진 분석화면(A2)에서 근거·불확실성을 보여주고, 승인된 결과만 환자·보호자에게 공개.
5. 검토/수정/승인/의뢰/수락/제공 완료 및 **미회신 이력**을 정합성 있게 분리.
6. 신구 정책버전과 급여/긴급지원의 **자격 검토 경계** 명시.
7. 기관별 초기 구축과 유지보수의 반복 비용을 줄이는 **어댑터 분리**.

**위 가설 중 어느 것도 아직 '기존 공공망보다 우수하다'고 입증된 사실이 아님.**

## 4. 사업상 진입 우선순위

| 접근 | 장점 | 장애 | 제안 |
|---|---|---|---|
| 별도 독립 폐쇄형 연계망 | 기업이 UX/데이터흐름 통제 | 국가/공공망 기능과 중복, 기관 확보비 | 초기 주력으로는 비추천 |
| **병원 내부 사전평가·서류 초안·검토 제품** | 실제 의뢰 이전에도 업무절감 실험 가능 | EMR 통합·예산·실무 인터뷰 필수 | 1차 검증 대상 |
| 공공의료연계망 연동/보완 | 기존망을 활용해 전체 환자흐름 연장 | 공식 연동·기관협약 미확보 | 실증 후 장기 목표 |
| EMR 업체 모듈 파트너십 | 기존 시스템 내 UX·영업망 활용 가능 | 제휴·연동·수익분배 문제 | 대안 GTM |
| 병원-지자체용 공공사업 | 다기관 협력 프로젝트 | 조달, 운영책임, 개발비용 증가 | 중장기 |

## 5. R02 완료 전 필수 증거

- [ ] 공개 데모/설명서·현장 시연으로 기존 공공망의 입력 자동화·서식 작성·회신·사용성 확인.
- [ ] 업무 담당자 인터뷰: 종이/PDF/엑셀·EMR·국가 시스템 사이 실제 중복 입력·누락이 어디서 발생하는지.
- [ ] 개인병원/종합병원/상급종합병원/책임의료기관별 전산·도입 구조의 실제 차이.
- [ ] 병원별 퇴원연계/전환관리 대상자 선별 규모(최종 지자체 의뢰 건수와 구분).
- [ ] 경쟁사업자의 공개 조달계약/가격 또는 견적, 시장의 예산 출처.
- [ ] 국민건강보험/복지행정 시스템의 공식 연계 API·계약·정보접근 범위.
- [ ] 비교 테스트 항목: 사용자 클릭 수, 검토·수정시간, 누락건수, 업무 전환 횟수, 회신 지연 발견.

## 6. R02 판정

**공개자료 기능 중복과 시장 진입 위험은 확인. 실제 미충족 업무·기술적 우위·구매 가격은 미검증.**

R01과 함께 사용할 첫 제품 가치제안:
'의료기관 퇴원·전환관리 업무에서 기존 정보를 재활용해 평가·의뢰 자료를 준비하고, 전문가 검토·환자 설명·진행상태를 안전하게 연결하는 소프트웨어.'
