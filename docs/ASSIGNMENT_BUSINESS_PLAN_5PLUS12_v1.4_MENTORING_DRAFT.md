### 3. 시장 규모·성장성

- **수요 배경:** 2026년 65세 이상 인구 약 1,112만 5천 명(21.6%)이라는 기존 계획서 공식 통계와, 2023년 노인실태조사(스마트폰 보유 76.6%, 정보화사회 적응 어려움 67.2%)를 참고한다. 이는 우리 앱의 유료 수요를 뜻하지 않는다.[1][2]
- **제도 배경:** 2026년 지역사회 통합돌봄 시행 및 퇴원 연계 정책을 관찰하되, 공적 운영체계를 민간 플랫폼 구매시장으로 환산하지 않는다.[3]
- **조사 가능한 초기 기관군:** 기존 문서상 상급종합병원 47곳과 종합병원 337곳 **합계 384곳**은 병원 종별·기준 시점이 붙은 *조사 범위 후보*로만 활용한다. 수치 원문 대조·범주 중복 여부를 제출 전 재확인한다.[4]
- **실제 구매시장:** 병원별 퇴원환자 규모, 기존 시스템·업무 흐름, 구매자, 정보보안 요건, 소프트웨어 예산, 지불의사를 확인한 뒤 TAM/SAM/SOM을 산정한다. 384곳 × 임의 가격 = 실증 시장규모라는 표현은 금지한다.

### 4. 제품·기술 스택·엔진

**현재 개발 자산:** 합성 데이터 전용 HTML·CSS·JavaScript MVP. A1 환자 목록 → A2 6개 영역·30개 항목 **규칙 기반 업무 검토 평가** → A3 의료진 역할 기반 검토·승인·발행·개정·철회 → 환자용 B의 현재 유효 발행 정보 안내.[5][6]

환자용 B는 오늘·일정·도움·내 정보, 큰 글자, 유효 발행본 확인, 승인 PDF 열람/다운로드 및 발행본별 '이해 확인' 등을 합성 데이터로 시연한다. A3→B 연결은 실제 병원 서버 연동이 아니라 브라우저 localStorage/IndexedDB를 사용하는 동일 origin 개발 시연이다.

**현재 미구현:** 의료기관 본인인증, 서버 권한, Firebase/EMR, 실제 환자 데이터, 의료 AI 임상 예측, 실제 이동·요양 서비스 조회·접수·예약 확정, 실제 파트너 API 연동. 의료진 승인과 의료계획의 공개 경계를 기존 안전계약대로 유지한다.

### 6. 가격·비즈니스 모델 — 멘토링 ① 반영

**B2B2C:** 의료기관이 기본 구독·도입 비용을 부담하고 환자·보호자는 핵심 퇴원안내를 무료로 이용한다. 교수님 조언을 반영해 카카오 T 등 이동·요양·돌봄 사업자 정보가 환자용 서비스에서 **연계 가능한 자원으로 탐색**되는 흐름과, 병원에 제공할 **선택형 운영 프리미엄**을 별도로 검토한다.

| 수익 항목 | 가격(검증 전 가정) | 과금 대상 / 경계 |
|---|---:|---|
| 병원 기본 구독 | **월 50만 원** | 의료진 검토·발행·환자 안내 기능 |
| 기관 최초 설정·교육 | **1회 200만 원** | 초기 구축 범위 제한, EMR 연동 제외 |
| **선택형 연계 프리미엄** | **월 +20만 원** | 이동·돌봄 정보 관리·상담 경로·상태안내 등 **후속 기능**, 가격 가설 |
| 환자·보호자 핵심 안내 | **무료** | 선택형 프리미엄 미구매 병원에서도 핵심 안전안내 유지 |
| 별도 보안/EMR·맞춤 개발 | 협의 후 견적 | 실제 개인정보 처리·기관 연동 전 별도 조건 |
| 사업자 연계·환자 의뢰 건당 수수료 | **매출에 반영하지 않음** | 제휴·계약 없음; 알선·유인·급여·광고·개인정보 규제 검토 선행 |

**연계 기능의 제안 흐름:** 서비스 종류·공식 자격·비용·문의처 탐색 → 명시적 선택과 동의 → **해당 서비스사에서 실제 요청/접수/확정**. 화면에서 '정보 보기/문의/신청/접수/확정'을 혼동하지 않는다. 병원 의료진이 발행한 퇴원 안내와 공적 기관의 장기요양 자격·개인별 지원계획은 권한과 책임이 다르다.

**시장 인접 사례(당사 제휴 아님):** 카카오모빌리티는 **2026년 3월 29일** 분당서울대병원에 디지털 취약 계층을 위한 **일반 택시 '대신 불러주기'**를 도입했다고 발표했다.[8] 교수님이 예시로 제시한 **'벤티 환자 이송 사업' 자체의 출시·사업 조건·계약 여부는 미확인**이다. 일반 택시와 의료적 이송·구급차를 동일 서비스로 표시하지 않는다. 의료법 제27조 제3항의 환자 소개·알선·유인 규제 적용 여부 등은 서비스 방식에 따라 전문 법률 검토가 필요하다.[9]

**고객 가치 검증 질문:** 병원이 기존 퇴원교육·외부 안내 업무에서 어느 작업이 줄거나 개선되는지, 최신 정보 관리 책임을 누가 맡는지, 월 기본료와 프리미엄에 각각 지불의사가 있는지를 면담한다.

### 7. 특허·지식재산 현황

케어브릿지랩·「퇴원 후, 나의 하루」의 상표, 웹앱 코드 저작물 별도 등록, 평가/발행 기술의 특허는 **출원·등록 사실 미확인**. KIPRIS 상표 중복검색, 오픈소스·폰트·화면 자료의 이용조건, 공동개발 산출물의 권리관계 등 검토한다. 제3자 서비스 로고·브랜드를 임의 제휴표시로 사용하지 않는다.

### 8. 1라운드 성과 및 향후 검증 — 멘토링 ②·③ 반영

**현재 성과:** 합성 데이터 MVP와 개발자 테스트·R13 실험 도구 제작. **실제 사용자 조사는 아직 미실시**.[6][7]

**실사용자 검증 계획:**

| 대상·모집 *목표* | 확인할 질문 | 기록 지표 |
|---|---|---|
| 고령 사용자 5~10명 | 오늘 할 일·복약안내·일정·도움 경로를 스스로 찾는가 | 성공/실패, 탐색 시간, 도움 요청 수, 위험한 오해 |
| 보호자 2~3명(가정) | 본인·보호자 정보, 전화·인쇄·큰 글자 중 필요한 방식 | 선호 기능, 이해 어려운 표현, 실제 행동 |
| 퇴원교육·연계 의료진 | 무엇을 반복 설명하고 누가 발행 정보 최신성을 유지하는가 | 현재 업무, 오류 경로, 추가 입력 부담 |
| 병원 구매/보안 담당자 | 실제 구매 부서·예산·인증·법률·유지비 조건은 무엇인가 | 구매 조건, 반대 사유, 가격 민감도 |

**R13 설계 기반 과업:** T1 승인된 복약 관련 안내를 찾아 설명하기; T2 다음 외래/검사가 실제 확정인지 확인하기; T3 주의사항·문의처 찾기; T5 자신의 말로 이해한 내용 설명하기.[7] 이동·돌봄 연계는 기능 구현·공식 정보 확인 후 별도 T4로 시험한다. 실험 자극물은 동일 발행본의 서면/모바일 안내로 통제하되, 작은 파일럿의 차이를 임상효과로 일반화하지 않는다.

**실사용자 연구 안전:** 실제 환자 모집·병원 내 개인정보 접근·진료정보 수집은 기관 승인·필요한 연구윤리/정보보호 검토를 먼저 수행한다. 초기 일반인·동료 테스트는 익명·동의·합성 사례만 사용한다.

| 비용(월 고정비 300, 유료기관 월 변동비 10, 신규기관 도입 직접비 200) | 미산정 | 4,120 | 4,880 |
| **기준 단순 영업손익** | **미산정** | **-3,120** | **-1,680** |

**프리미엄의 효과를 따로 측정:** 2029년 기존 고객 2개 병원이 프리미엄을 각 12개월 구독하고, 프리미엄 월 요금 +20만 원·추가 월 변동비 8만 원으로 가정하면, 추가 매출 `2×12×20=480만 원`, 추가 변동비 `2×12×8=192만 원`, 기준 영업손익은 **-1,392만 원**으로 개선되지만 적자가 남는다. 프리미엄 추가 초기비·보안·제휴·영업비·세금은 별도 미산정이다.

**기본 구독 BEP 참고:** 월 고정비 300만 원 ÷ (기본료 50만 원 - 기관당 변동비 10만 원) = 7.5 → **최소 8개 병원**. 2029년 목표인 6개 기관은 이에 못 미친다. 프리미엄이 실제로 판매되거나 수익이 보장된 것으로 말하지 않는다.

**로드맵:** 2026 Q4 합성 MVP·멘토링 반영·조사도구 준비 → 2027 사용자·보호자 사용성 파일럿 및 의료진/병원 구매자 별도 인터뷰 → 법률·요양자격·서비스 상태/신청 경로 대조 → 2028 조건부 시범운영 및 기관 도입 시도 → 2029 조건부 기능·프리미엄 고도화.

### 12. 자유 기입 — 사업화 가치 및 단계적 확장

환자 중심 기본 경험(승인된 퇴원계획·다음 행동)과 지역사회 서비스 탐색은 한 제품에서 접근할 수 있지만 **서로 다른 정보·권한 계층**으로 운영해야 한다. 의료진의 승인 기록이 민간 서비스 이용 가능·지원자격·신청 접수·예약 확정을 대신하지 않는다. 환자의 클릭이나 관심 표시를 병원으로 자동 전송하거나 제휴 사업자에게 광고 타깃으로 제공하지 않으며, 동의·제3자 제공·광고 여부·공공/비제휴 대안·상태 정보를 구별할 계획이다.

**향후 개발은 이 문서만으로 시작하지 않는다.** 설계 채팅에서 기존 승인 UX와 공유 상태·발행/철회 안전계약을 검토하고, 범위를 확정한 뒤 별도 브랜치에서 구현한다. 멘토링 반영 문서는 새 기능 구현이나 실제 제휴를 의미하지 않는다.
