## 2. 후보별 가설 검증 카드 — 첫 6개부터

### BM-01 병원 SaaS
- **고객문제 가설:** 퇴원·지역연계 대상자 확인과 발행물 관리가 단절되어 간호사/의료진의 재작업을 유발한다.
- **증거 확보:** 기존 업무 프로세스 2~3건에 대한 인터뷰 또는 합성 시나리오 기반 전문가 피드백; 작업 단계·업무시간 측정 계획 수립. 실제 협력 확정 아님.
- **판단 게이트:** 구매/운영 의사결정권자, 현장 사용자, 서버·권한 필요요건을 구분 확인 후 가격 가설.
- **보류 기능:** EMR 실제 연동, 임상 위험도 자동 판단·의료진 승인 대체.

### BM-02 숙박
- **고객문제 가설:** 지방 외래 환자가 진료 전후 교통·체류와 접근성 숙소 조건을 한 번에 비교하기 어렵다.
- **고객 질문:** 숙박이 필요한 이유/빈도, 예산, 동행 여부, 휠체어 이동 동선, 지하철/택시 접근성, 취소 조건, 일정 변경 대응.
- **제휴 가설:** Agoda·Trip.com·Expedia의 공개 프로그램부터 적격성 확인. Booking.com은 계약형 API, Airbnb는 일반 퍼블리셔 모집 제한 및 개별 협의 가능성, 여기어때·야놀자 상업 앱 제휴 여부는 미확인. **어느 업체와도 제휴하지 않음.**
- **작은 실험:** 외래 일정에서 ‘숙박이 필요한가요?’ → 무장애 조건/동행/교통/취소 조건 설정 → 외부 공식 검색. 유료 링크와 무료/직접 숙소 문의 대안 동등 제공.
- **판단 게이트:** 플랫폼 가입 가능·광고 표시·정산 기준·장애인 접근성 데이터의 신뢰성과 최종 확인 주체.

### BM-03 의료기상사·복지용구
- **고객문제 가설:** 준비물의 임상 적합성과 실제 구매/대여·보험 급여·배송 조건이 환자에게 혼재된다.
- **작은 실험:** ‘의료진 확인 준비물’ → 일반 의료기기 판매/대여·장기요양 복지용구·공공 보조기기·일반 생활제품 **4경로** → 배송·설치·소독/회수 조건 비교.
- **공급자 검증:** 등록/신고·재고/배송·대여/회수·위생·지역·사후관리 실사. 실가격/재고는 계약 전 실시간 표시 금지.
- **판단 게이트:** 의료기기법·장기요양보험 요건과 의료진 경제적 이익 제공/알선 금지를 법률 확인 후 수익화 검토.

### BM-04 이동지원
- **고객문제 가설:** 목적지 확인·탑승할 보조기구·도착 후 도움의 **세 과업**이 실제 예약 과정에서 분리되어 누락된다.
- **작은 실험:** 기존 3단계 택시 화면을 활용하여 사용자 이해 확인. 외부 택시 호출/결제/차량 배정은 미구현 표시.
- **판단 게이트:** 카카오모빌리티와의 공식 파트너 자격·지원 API·장애인 차량·보험/책임 경계를 확인하고 연동 여부 결정.

### BM-05 복지·공공지원
- **고객문제 가설:** 환자가 무료 공공 경로를 모르고 유료업체부터 찾게 된다.
- **작은 실험:** 장기요양 인정/복지용구/보조기기/지자체 통합돌봄 공식 페이지를 연결하는 분기형 안내. 앱은 자격·금액·최종 승인 판단을 하지 않음.
- **판단 게이트:** 국가기관·지자체 자료 갱신 책임, 서비스 신청/회신 실제 주체, 환자별 데이터 최소화.

### BM-06 보호자
- **고객문제 가설:** 퇴원 교육문서 이해와 실제 교통·숙소·식사·준비물 분담이 서로 다른 사람에게 끊어진다.
- **작은 실험:** 가상 보호자에게 준비물/이동/방문 일정 선택·기록지 출력; 공유하기 기능은 인증·동의·권한 설계 전 시연 수준.
- **판단 게이트:** 실제 보호자의 도움 수요와 환자 허가 범위를 조사.

## 3. 단계별 사업성 산정 규칙 — 가정과 실측 분리

숫자를 만들기 전에 **고객/결제주체 → 서비스당 매출 → 제휴 가능성 → 운영원가 → 준법 비용**을 구분한다.

- **기관 SaaS:** 연간 계약 가능 기관 수 × 연간 계약단가 × 실계약 전환율 − 호스팅·보안·온보딩·CS·유지보수비.
- **숙박:** 해당 외래 방문객 중 체류 필요 비율 × 외부 제휴 링크 이용률 × 실제 정산 인정 예약 비율 × 건당 정산 수익. **현재 모든 인수는 미측정**.
- **보조기구 업체용 SaaS:** 유료 계약 공급업체 수 × 월 사용료 − 공급처 DB 검증·지원·연동 비용. 환자의 의료기기 구매에 따른 소개 수수료와 다름.
- **기관용 공공/보호자 모듈:** 기관당 서비스 운영·통합 비용을 포함한 별도 단가 가설. 임상 성능·의료비 절감 입증 전 임상성과 기반 성과보수는 가정하지 않는다.

## 4. 다음 채팅에서 할 결정

1. 첫 번째 사용자 시나리오는 **근골격계 퇴원 고령 환자**와 **지방에서 방문한 외래·보호자** 중 무엇을 택할 것인지.
2. BM-02 숙박, BM-03 보조기구, BM-04 이동 중 다음 **목업 후보 1개만** 선택할 것인지.
3. 병원 B2B SaaS와 제휴 서비스를 앱 정보구조상 분리할지, 동일 ‘생활·이동’ 영역 아래 정리할지.
4. 본격 제휴조사 단계에서 실제 업체 3~5곳의 가입/영업/신고/지원범위를 확인한 후 추가 구현할지.
