# 케어브릿지랩 — 첫 고객·파트너 실사 가이드 v0.1 (Track B)

작성: 2026-10-23 · 상태: **인터뷰/파일럿 설계안. 실사·접촉·계약·가격검증 NOT RUN**.
참고: `docs/business/HIGH_POTENTIAL_BM_SHORTLIST_v0.1.md`, `docs/research/R13_COMPARABLE_SERVICES_AND_EQUIPMENT_CONCEPT_v0.1.md`.
전략: **병원 SaaS = 본업**, 보조기구 공급업체 운영 SaaS와 숙박 안내 = 실험적 보완 수익축. 현 단계에 EMR/API/제휴/거래 기능 구현 없음.

## 1. 조사의 실제 목적

세 모델 각각 **누가 문제를 겪는가(사용자), 누가 대가를 내는가(구매자), 어떤 시점에 의사결정하는가, 문제의 빈도·비용은 얼마인가, 실제 대체재는 무엇인가, 법적 제약을 넘을 수 있는가**를 확인한다.
- 서비스 이름/아이디어에 대한 호감이나 가상 가입 의사만으로 사업성을 입증하지 않는다.
- 수익모델은 인터뷰에서 실제 **지출·업무·계약 흐름**이 확인되기 전까지 가설로만 둔다.
- 자료 수집은 비식별·집계 원칙. 개인 환자/의료기기 처방/구매정보/기관 내부기록/가격표를 무단으로 GitHub에 업로드하지 않는다.

## 2. 공통 진행 멘트와 기록 양식

**시작 멘트** (실제 적용 전 조사 성격·동의 필요 여부 검토):  
"가상의 퇴원·지역사회 연계 서비스를 기획하는 학생 프로젝트입니다. 현재 병원이나 업체와 정식 계약한 제품이 아니며, 실제 환자정보나 내부 기밀자료를 요청하지 않습니다. 지금 사용하는 방식과 불편을 이해하려는 목적입니다. 답하지 않거나 중단하셔도 됩니다."

**공통 질문:** 가장 최근 비식별 사례에서 그 일이 발생한 시점과 구체적인 업무 순서를 말해 달라 → 가장 오래 걸린 단계 → 기존 해결방법 → 발생 빈도 → 반복 비용 → 의사결정자·예산 주체 → 신규 시스템이 도입되려면 필요한 조건을 확인.
**기록 필드:** 코드(H01/S01/L01 등), 역할, 기관 유형, 가명/비식별, 응답 직접 요지, 관찰된 사건(있으면), 정량 수치의 기간·분모·출처, 확실성 `응답/문서로 확인/추정`, 후속 확인 주체, 법률·보안 이슈, 수집 동의 범위.

## 3. 병원 B2B SaaS (H)

### 인터뷰 대상 제안
퇴원업무 담당 간호사·사회복지 담당자 등 현장 사용자 2~3명, 병원 정보보호/IT 담당 1명, 구매·운영 예산 결정자 1명 이상. 모두 **접촉 목표**이지 인터뷰 완료 실적 아님. 의료진 한 명의 호감이 병원 구매 승인으로 이어진다고 추정하지 않는다.

### 핵심 질문
1. 마지막 퇴원·지역사회연계 사례에서, 최초 대상자 확인부터 퇴원안내·지역연계까지 **어떤 시스템과 서류**를 이동했나요?
2. 같은 환자 정보를 반복 입력하거나 통화·팩스·메일로 재확인한 단계가 있었나요? 최근 **한 달** 빈도와 **건당** 시간이 얼마나 되나요? 기억에 근거한 추정이면 그렇게 표시.
3. 누락된 정보를 발견했을 때 누가 확인하고 승인하나요? 변경·철회·재발행 기록은 어디서 관리하나요?
4. 기존 EMR/퇴원계획/지자체 시스템으로 해결되는 부분과 남는 불편은 무엇인가요?
5. 병원 도입 전 요구되는 계정·권한·감사로그·보안심의·연동·교육·유지보수 조건은 무엇인가요?
6. 개선 사업의 발의자/구매결정자/실제 비용 센터는 누구이며, 유사 도구에 **실제 지출한 경험**이 있나요?
7. 합성 시연 후 현재 절차와 비교해 오히려 입력이 늘거나 위험해지는 지점은 어디인가요?

### 정량화
- 월 관련 퇴원·연계 건수(응답 기간), **건당 불필요한 반복 입력 분**(업무측정 필요), 승인/발행 지연 빈도, 확인/회신 실패 빈도, 도입 시 교육/유지비.
- 추후 편익 가설: `월 반복 건수 × 건당 절감 가능한 분 × 시간당 완전인건비 ÷ 60`. 곧바로 기관이 지불할 수 있는 가격으로 등치하지 않음.
- `GO` 검토: 서로 다른 현장 사용자에게서 구체적 반복 병목이 확인되고, 구매자/IT의 도입·보안 검토 경로가 존재. `NO-GO`: 기존 체계가 충분하거나 승인/입력업무가 오히려 증가, 보안·조달 장벽 해소 가능성 없음.

## 4. 보조기구 공급업체 B2B 운영도구 (S)

### 인터뷰 대상 제안
**서로 다른** 장기요양 복지용구사업소와 일반 보조기구 판매·임대사업자 등 3~5곳에 예비 질문(실제 설문·채용/영업 아님). 의료기기 해당 제품 및 급여품목 규정 구분.

### 핵심 질문
1. 고객이 장비를 요청한 뒤 **이용자격 확인 → 품목/재고 → 서류 → 배송·설치 → 반납/회수/위생/수리** 중 어디서 시간이 가장 드나요?
2. 지난 한 달에 재요청·배송 지연·대여 만료·반납 누락 등이 몇 번 있었나요? 기록 근거가 있나요?
3. 현재 재고·배송·반납 정보를 엑셀·종이·ERP·전용 SW 중 무엇으로 관리하나요? 현 도구에 쓰는 비용은?
4. 병원에 추천/환자 유인 대가를 지불하지 않고도, **업체 내부 운영도구**에 월 사용료를 낼 이유가 있나요?
5. 누가 계약하고, 직원 몇 명이 쓰며, 어떤 교육/전화지원·장부/급여 처리와 연동해야 하나요?
6. 허가·인증·판매/임대업 신고·대여 세척·사후관리 등 해당 품목별 규정과 책임은 누구에게 있나요?

### 정량화
월 구입/대여 건수, 배송·회수 건수, 재작업 비중, 현 소프트웨어 비용, 시간, 공급업체 수, 고객지원 원가.
- 초기 B2B SaaS 수익 가설: `유료 업체 수 × 월 사용료 − 업체 온보딩/지원/유지비`; **가격 및 전환율 미확정**.
- `GO` 검토: 반복적 운영비와 명확한 결제권자가 존재하고 법률 검토 가능한 업체용 기능에 대한 지불 가능성 확인.
- `NO-GO`: 비용을 줄일 운영 병목이 없거나 실질적 매출이 병원·의료인 환자 소개 수수료에만 의존.

## 5. 숙박·장기체류 (L)

### 인터뷰 대상 제안
비식별 타지역 외래 방문 경험 성인 보호자/일반인 3~5명(연구 참여·윤리 판단 별도), 병원 근처 숙박사업자·공식 제휴창구 2~3개. 실제 환자 사례를 요구하지 않는다.

### 핵심 질문
1. 가장 최근 원거리 진료 동행에서 실제 **숙박을 했는지**, 일정과 지역, 숙박 필요 이유(당일 왕복 가능 여부)를 개인정보 없이 설명해 주세요.
2. 숙박을 하지 않은 경우 가장 큰 이유는 무엇인가요? 숙박을 했다면 예약에 사용한 채널·기간·예산 범위는?
3. 휠체어 동선, 엘리베이터, 침대/욕실, 이동시간, 환불·일정 변경 조건 가운데 무엇을 가장 확인하기 어려웠나요?
4. 공식 숙박사이트와 차별화된 정보가 실제로 필요했나요? 직접 확인하신 방법은?
5. 제휴가 없다면 외부 일반 링크만 제공하는 서비스도 도움이 되나요?
6. 숙박업체 측에는 객실 접근성 정보가 검증 가능한지, 고객지원·취소·환불 책임이 무엇인지, 신규 제휴 가입/정산 규칙이 어떠한지 확인.

### 정량화
원거리 외래 방문자 수 × 숙박 필요 비율 × 링크 사용 비율 × 실제 완료·인정 예약 비율 × 건당 정산액. 모든 요소 현재 미측정.
- `GO` 검토: 명확한 이용자 세그먼트, 확인 가능한 정보 신뢰성, 공식 프로그램/직접 계약 자격 존재.
- `NO-GO`: 수요 미확인, 플랫폼으로 해결할 새로운 마찰 부재, 접근성 미확인·정산 불가, CS 비용 초과.

## 7. 의료정보 및 상업적 이해상충 방어선
- 합성 화면 시연만 활용, 인터뷰 시 환자 성명·진단·입원기간·처방 내용·병원 내부 계약정보 등 요청하지 않는다.
- 공공급여 여부는 공단·지자체 등 법적 권한자가 판단한다. 민간 숙박·보조기구·교통 이용을 임상 권고로 표시하지 않는다.
- 의료기기 판매·임대업, 경제적 이익 제공, 개인정보 민감정보, 광고/제휴 고지는 실제 계약·서비스 전에 전문 확인.
- 보호자 자동 권한 및 제3자 데이터 제공 기능은 후속 보안·법률·동의 체계 전에는 구현하지 않는다.

## 8. 다음 실행 순서(완료 아님)
1. R13 전문가 소스 워크스루 결과와 별도 브라우저 검증 기록을 완성한다.
2. 기관 역할별 위 질문을 각 **6~8개**만 골라 비유도성 검토 후 예비 인터뷰 준비.
3. 구매자/현장/업체의 응답을 분리 집계해 빈도·비용·규제·구매조건 가설을 업데이트.
4. 인터뷰 근거가 축적되면 비의료 공급업체 도구 또는 숙박 외부정보 카드의 2차 목업 선택. 기존 환자앱 수정과 광고·제휴를 자동 승인하지 않는다.
