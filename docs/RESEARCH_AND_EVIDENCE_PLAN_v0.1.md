## 3. 발표 방어를 위한 핵심 질문 (답 없으면 '가설'로 표기)

1. "퇴원연계의 현재 병목"을 직접 측정했나?
2. "기존 EMR/공공망과 차별화"는 비교표·실무 자료로 입증했나?
3. "의료 AI"가 실제 ML 모델인지 규칙자동화인지 정확히 설명했나?
4. 고령인구/장기요양비를 직접 SW 시장으로 오인하지 않았나?
5. 협약병원 수와 실제 유료 구매 가능 고객을 구분했나?
6. 단가를 어떤 계약사례·업무 편익·원가로 설명하나?
7. 병원 도입 시 누가 비용을 결재하며 보안·EMR 연동을 누가 승인하나?
8. 연계 수당과 우리 회사 매출을 혼동하지 않았나?
9. 정책적 자격·지자체 판정과 의료진의 임상 판단을 혼동하지 않았나?
10. 개인정보, 의료기기 가능성, 의료행위 알선·소개 제한을 검토했나?
11. 실적·특허·협약·멘토링을 사실처럼 조작하지 않았나?
12. 어느 고객·환자·업무부터 검증할 건가?
13. 1년차 비용·현금흐름·BEP와 유지보수 부담을 설명할 수 있나?
14. 한 병원에 맞춘 개발이 다른 병원에도 팔리는 구조인가?

## 5. 근거 레지스터 작성 원칙

각 발표 주장에 다음 필드를 붙인다.

`claim_id | 주장 | 단위/대상 | 기준연도 | 원문 기관·URL·쪽수 | 확인일 | 자료 유형 | 검증상태 | 발표 사용 여부 | 한계`

- **확인됨:** 원문 수치·정의·기간·대상 직접 대조.
- **부분 확인:** 문서/보도자료의 존재만 확인, 수치·서식 상세 미검증.
- **가설:** 회사 가격, 고객 수, 시장진입·업무시간·AI 성능 등.
- **사용 보류:** 출처 불명, 연도 불명, 과장 위험.
- **실측:** 향후 사용자 테스트·고객 인터뷰 수행 결과. 모집·표본·방법 함께 표기.

논문·기업 발표의 성과는 원문 주체에 한정하며 자사 성과로 바꾸지 않는다.

## 6. 단계별 게이트

### Gate A — 기획근거 준비
- [ ] 2026년 원문 매뉴얼, 서식·개정 사항 대조 완료
- [ ] 기존 업무 AS-IS vs 제안 TO-BE 정리
- [ ] 경쟁·대체수단과 겹치는 기능 명확히 파악

### Gate B — 사업 타당성
- [ ] 첫 고객군·구매 결정권자·예산 경로 구체화
- [ ] 기관별 처리량·업무시간 추정 근거 확보
- [ ] 계약가격·원가·BEP의 가정 출처와 민감도 설명
- [ ] 시장규모 추계의 기관 모집단·가격 정의 확인

### Gate C — 발표용 근거
- [ ] 과제 5+12 전 항목 실제/계획/미확보 구분
- [ ] 통계·시장 주장마다 기관·연도·원문·한계 제시
- [ ] 가장 큰 법적·실무적 위험에 대응방안 기재
- [ ] 발표 예상 질문과 근거 자료 정리

### Gate D — 설계 완성 및 MVP 개발
- [ ] 고객 문제, P0 기능, 평가 근거, 상태·권한, 데이터·역할 흐름 확정
- [ ] 기능·예외·회귀·사용성 테스트 수용기준 확정
- [ ] 가상 데이터 시연용 MVP 구현 착수 승인

**현재 단계는 Gate A 이전.** 연구를 실제 수행하지 않은 항목은 체크하지 않는다.
