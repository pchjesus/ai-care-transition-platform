## 1. 새로운 사용자 요청의 배경

지도교수 구두 피드백 세 가지:

1. 카카오 택시(벤티 환자 이송 구상 언급)·요양업계 등과의 연계를 검토하여 병원에 추가 가치를 제공할 수 있는 수익모델 및 환자 앱 연계 진입점 고민.
2. 실제 사용자 인터뷰와 과업 관찰로 필요성·사용성을 검증.
3. 환자 화면의 현재 편안한 색감·정보 강조는 유지하는 한편 고령층이 중요시하고 익숙한 정보·표현·조작을 직접 확인하여 직관성 개선.

사업계획서 새 버전: `docs/ASSIGNMENT_BUSINESS_PLAN_5PLUS12_v1.4_MENTORING_DRAFT.md`.

## 2. 확정사항과 검토사항 구분

**유지할 확정사항:** 환자 중심 서비스, A1→A2→A3 승인·발행 뒤 유효한 정보만 B에 표시, 환자별 입원건/버전/철회 및 저장 실패 보존, 합성 데이터, 기존 환자용 B 디자인·기능. 기본 안내는 환자 무료.

**검토할 가설(결정/구현 아님):** `연계`라는 새 탭 vs 기존 `도움` 하위 진입점, 일반 이동/방문요양/복지용구 안내 범위, 병원용 정보 최신화 도구, 월 +20만원 선택형 프리미엄, 실제 서비스사 API/계약.

**법적·안전 경계:** 일반 택시 호출 ≠ 의료적 환자 이송, 의료계획 ≠ 요양·지자체 공식 지원계획, 링크 ≠ 신청, 로컬 요청 ≠ 접수, 신청 ≠ 확정. 환자 의료정보 제3자 제공이나 수수료·광고 우대 노출은 별도 심사 없이 하지 않는다. 카카오모빌리티 및 요양업체와 공식 제휴 없음.

## 3. 다음 설계 채팅 우선순위 (즉시 개발 명령 아님)

1. 기존 B `오늘/일정/도움/내 정보`와 새 연계 접점 중 어떤 정보 구조가 고령 사용자에게 더 직관적인지 2~3개 후보 비교.
2. 현재 승인 디자인(포레스트 그린/정보 위계)을 기준으로 환자 사용성과 접근성 평가 설계(크기·행동 라벨·정보 우선순위·전화/인쇄).
3. `도움`에 연계를 추가하더라도 현재 정상 동작·발행 정보 공개 계약·저장키·상태를 깨지 않는 독립 시안 설계.
4. R13의 T1/T2/T3/T5는 그대로, 신규 이동·돌봄 T4는 공식 정보 및 가상 데이터로 구현 후에만 시험.
5. 의료진·구매자·환자·보호자의 인터뷰 목표 및 표본 역할 분리. 실제 결과 수집 전까지 인터뷰 완료로 표시하지 않음.
6. 설계 합의 후 별도 브랜치 구현 → 직접 영향·회귀 검증 → 보고 → 배포/병합은 별도 승인.
