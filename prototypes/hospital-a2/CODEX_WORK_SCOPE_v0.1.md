# Codex 후보 작업 범위 v0.1 — A2 v0.5 이후

상태: **개발 계획·우선순위 검토용 / 실제 작업 미착수**. A2 v0.5의 UI 및 기본 동작은 사용자 승인됨. 환자용 v1.2는 이번 범위 밖.

## 지금 Codex에 적합한 작업 (작게 쪼개기)

### C0. 환경·테스트 표준화 (첫 작업 추천)
- GitHub `main`의 `prototypes/hospital-a2/` 구조·README·기존 테스트를 확인하고 실제 HTTP 서버에서 모듈형 `index.html` 실행.
- Chromium/Playwright에서 320/390/800/801/1024/1440px, 접이식 사이드바의 클릭·키보드·반응형·새로고침, 가상환자 3명·6영역·30개 입력·미평가/상충·모달·초기화를 점검.
- `build_standalone.py` 결과 `preview.html`이 소스 동작과 일치하는지 확인.
- PASS/FAIL/NOT RUN 구분. 실패한 회귀를 먼저 고치고 신규 기능은 넣지 않는다.

### C1. 구조·유지보수 개선 (C0 통과 후)
- `styles.css`의 과거 버전 덮어쓰기/중복 규칙을 컴포넌트별 토큰으로 정리하되 **시각적 차이는 최소화**.
- A1/A2/A3와 공통 환자·평가 모델을 구분할 준비, 데이터·규칙·UI 의존성 정리.
- 드래프트 평가상태/입력보존을 위한 mock repository 인터페이스 초안. 실제 환자자료, Firebase, 개인정보 저장 금지.
- 변경 전후 스크린샷 및 동일 테스트로 시각/기능 회귀 검증.

### C2. A3 실행 구현 (다음 채팅에서 A3 설계 승인 후)
- 의료진 검토/보류/수정/승인/발행/철회 상태 전이, 버전 및 감사정보.
- 미평가/상충이 있을 때 확인 없이 발행되지 않도록 규칙, 환자 공개용 내용 미리보기.
- 전문용어 기반 A2 정보와 환자용 행동안내의 변환 경계 검증. 기존 환자 앱 실제 연동은 별도 승인.

## Codex에 맡기지 않을 일 (지금은 설계·근거 우선)
- 자체 0~3 점수를 검증된 임상 위험척도로 승격, 재입원 확률 산출, AI 모델 훈련.
- 의료기관 EMR/Firebase/실환자 로그인 연결, 실기관 의뢰 또는 정보 전송.
- 공식 통합돌봄 선별 6문항을 자체 평가 6영역과 혼합.
- 환자용 v1.2 디자인 변경, 사용자 승인된 A2 v0.5 UI 전면 재설계.

## Codex 공통 개발 계약
현재 상태·코드·테스트를 읽고 **변경 전 구조/회귀·상태·저장·보안 위험 검토 → 최소 수정 → 기존 기능까지 검증**. 중간 결과는 별도 브랜치에서 확인하고, 본 저장소 `main` 반영은 사용자 승인 후 수행. 테스트를 실제로 실행하지 못하면 NOT RUN으로 보고.
