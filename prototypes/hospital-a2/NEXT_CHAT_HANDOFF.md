- 별도 디자인 레퍼런스: `pchjesus/design-kkakgi`, 2026-10-21 `main`에서 Universal v1.3 DRAFT 및 KRDS/Apple/Material 3 조사 확인. **v1.3은 정식 승인 전**.

- 병원용: A2 다영역 평가 목업 v0.5 (가상 고령 근골격계 퇴원환자 3명). A1은 목록 팝업, A3는 계획 초안 팝업만 있음. 실제 발행 기능 없음.

## 확정에 가까운 설계 계약
- 제품 흐름: **A1 환자/업무 목록 → A2 6영역 평가 → A3 의료진 검토·승인 → B 환자용 승인 계획**.
- 6영역: **의료 / 간호 / 약료 / 기능 / 사회환경 / 돌봄 연속성**.
- 영역당 입력 5개(필수 3개 + 추가 2개), 총 30개. 가상 환자 3명.
- 평가 등급: **0~3 + 미평가 + 상충**. 제품 자체 **업무 검토용 규칙**이며 검증된 임상 위험점수나 공식 선별 척도가 아님. 점수 경계·가중치·임상 타당도 미확정.
- 공식 통합돌봄 선별 6문항 ≠ 제품의 자체 6개 영역. 별도로 설계.
- 결측/상충은 자동 0점 처리 금지. 평가 근거·입력 출처를 추적하며 A3 검토 전 환자용 공개 금지.
- 사용자 선택: A2 우선위계 **환자 → 판단/확인 → 6영역 입력 → 세부 근거 → A3 초안**.
- 디자인 v0.5: 흰 작업영역 + `#214B3B` 다크 그린 사이드바, PC 접기/펼치기(242px/78px), 흰 바탕·진녹색 글자 `D.` 로고, 모바일 상단메뉴, 반복 시연 면책문은 별도 빠른 사용 안내로 이관. 합성 환자 ID와 `가상` 표시는 UI에 남김.

## 다음 채팅의 우선 과제
1. **사용자 v0.5 UI 기준선 승인 확인됨.** 미완료 기능·안전·임상 검증의 승인으로 오해하지 말고, 기존 디자인/기능을 보존한다.
2. A2 30개 필드에 대해 공식 서식·검증 연구·원천 데이터·직종 책임·상태 정의를 하나씩 확인한다. 현재 규칙은 데모일 뿐.
3. A3 본화면 설계: 누락·상충 해결, 의료진 변경/보류/승인/발행, 환자용 미리보기, 버전/첨부/PDF 일치, 철회/재승인. **가상의 승인 상태를 실제 승인으로 보고하지 않도록** 분리.
4. A1 실제 목록/필터/상태와 A2·A3 간 초안/입력 저장 통합을 설계.
5. 통합 설계가 확정되면 Codex에 구조 정비, Firebase 대비 저장소 인터페이스, 실제 HTTP/Playwright 기능 회귀를 맡긴다. 먼저 `CODEX_WORK_SCOPE_v0.1.md`의 P0 테스트·정리 작업부터 검토한다. 실제 환자정보나 실제 병원 시스템 연결은 하지 않는다.
