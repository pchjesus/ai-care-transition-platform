# 케어브릿지랩 · 의료진 UX 2.0 v0.6

원본 UX 2.0 v0.5 화이트 UI·PC/모바일 접이식 메뉴·A2 입력/저장/인계 동작을 보존한 채, 기존 **A3 계획 작성·근거·문서 계약**을 연결하는 개발 브랜치 체험본.

## 실행

저장소 루트에서 다음을 실행한다.

```bash
python -m http.server 8765
```

그다음 브라우저에서 `http://localhost:8765/prototypes/hospital-ux2-v06/index.html`을 연다.

- A1 → SYN-002(기본 정상 사례) → 퇴원계획 작성: 안내 문구 저장, 근거 연결, 검토 확인
- A1 → SYN-001: 약물 안내 근거 이슈, 역할별 해결 시연
- A1 → SYN-004: 발행된 기록은 수정 금지, 원본 A3에서 개정 필요
- 문서·첨부: 4MB 이하 PDF만 허용. SHA-256·이름·크기와 분류/공개범위/검토 상태를 저장. **PDF 원본 자체는 저장되지 않으며 현재 탭 메모리에만 보관**한다. 새로고침 또는 원본 A3로 이동 후 동일 파일 재첨부 필요

`file://`로 단일 HTML을 열면 기존 A3 공유 모듈을 불러올 수 없으므로 **계획·문서 실제 저장은 지원하지 않는다.** HTML과 `integrated-v10` 폴더가 동일 출처의 HTTP(S) 경로에 있어야 한다.

## 설계·안전 경계

- 기존 `prototypes/integrated-v10/a3/storage.js`, `workflow.js`, `source-library.js`을 직접 호출한다. A2 저장·인계는 v0.5 구현을 유지한다.
- 정식 저장 키는 원본 `care-transition-integrated-v10-a3-synthetic-only`; 파일 저장 시 기존 원본 저장소의 schema 2와 compare-and-write를 이용한다.
- 환자 식별은 SYN 합성 사례 ID에 한정하며, 다른 환자의 근거 연결은 차단한다.
- 현재 발행/철회된 계획 수정 금지. 승인·검토 요청된 초안의 데이터 변경 시 원본 A3와 동일하게 상태 DRAFT 전환 및 승인 무효화 기록을 남긴다.
- 안내문 변경·근거 연결·일정·PDF 메타데이터 변경 시 항목별 검토를 다시 수행한다.
- 직종별 항목 검토 및 미해결 항목 해결은 원본 A3 역할 규칙을 따른다. 역할 전환은 실제 권한 인증이 아닌 **합성 시연**이다.
- PDF 메타데이터의 REVIEWED 상태만으로 발행 가능한 것이 아니다. 실제 원본 파일이 승인 과정에서 이용 가능한지도 기존 A3가 확인한다.
- 의료진 검토 요청·최종 승인·발행·개정·철회는 여전히 원본 A3 화면의 책임이다. v0.6에서 새 구현했다고 주장하지 않는다.
- 기존 발행 스냅샷·환자 공개 자료는 이 화면에서 수정하지 않는다. 환자 앱 B에 대한 직접 연동 및 새 홈 재설계는 다음 범위다.
- 실제 환자정보, 예약, 의료지시, 임상 검증, 의료기관 제휴 또는 서버 저장 기능이 아니다.

## 구성

- `index.html`: v0.5 원본 HTML의 독립 사본 + v0.6 에셋 연결
- `integration.js`: UI와 원본 A3 계약 간 연결
- `integration.css`: v0.5 기본 디자인을 변경하지 않는 영역 한정 스타일
- `tests/browser_smoke.py`: 브라우저·환자 간 분리·저장/복원·PDF 원본·동시 수정·손상 저장 회귀검증
- `.github/workflows/hospital-ux2-v06-qa.yml`: v0.6 QA 및 기존 A3 Node 테스트

## 상태

작업은 `feat/hospital-ux2-v06`에서만 수행한다. `main` / `gh-pages` 미변경. 브라우저 QA의 최종 PASS/FAIL은 해당 브랜치 GitHub Actions 결과를 기준으로 확인한다.
