# Codex — 환자용 v1.2 작업 범위 (독립 보존, 파일 제공 후 진행)

## 실제로 확인한 자료/접근 한계
- 이전 대화의 독립 목업 `퇴원 후, 나의 하루` v1.2. **사용자 승인된 UI/기능을 기준선으로 취급**.
- Project Library의 `index.html`(약 321KB) 텍스트 검색을 통해 단일 HTML에 `render()`, demoRepository/localStorage, 가상 코드 로그인, 프로필 편집, PDF 오버레이, 메뉴, 글자 크기 및 시연 상태가 존재함을 확인.
- 원본 바이너리 materialize는 **접근 실패**. 이 ZIP에 환자용 원본은 포함하지 않으며, 전체 구조/회귀를 직접 실행 검증한 것은 아님.
- 반드시 사용자 또는 연결된 개발 환경에서 **정확한 v1.2 원본 `index.html`을 Codex에 제공**하고 기준본을 동결한 뒤 진행.

## 우선 검토할 회귀 위험 (정리 작업 아님)
1. 1파일 내 렌더 템플릿, 데이터, 이벤트 위임, 모달/PDF, 저장소를 '논리 구역별'로만 조사. 불필요한 전체 재분석/새 프레임워크 도입 금지.
2. 시연 코드 `CARE2026`은 **실제 인증 아님**; 가상 역할과 승인 상태를 실서버 보안으로 주장하지 않음.
3. 프로필 localStorage 로드/수정/저장/복원/초기화, 기관 업데이트 요청 시연값, 상태 갱신/충돌/잘못된 저장값을 검사.
4. HTML 주입/XSS 위험, PDF 보기/닫기·URL.revokeObjectURL/팝업 차단, 모달 포커스/키보드/Escape.
5. 홈·일정·도움·내 정보 사이 데이터 일치, 글자 크게 상태의 전 탭 반영, 320~1440px 가로 넘침.
6. 환자 전용 표시: 미발행/철회 안내 차단, 이전/새 계획 버전, 보호자 공유 거부, 외래 예약 미확정, 복약 정보의 임의 생성 방지.
7. 가상 로그인 클릭/Enter, 시연 코드 실패·성공 분기. 실제 개인정보 입력 또는 저장 확대 금지.

## 작은 작업 묶음
- **P-C0 (첫 실행, 변경 금지)**: UI 스냅샷/기능 목록, 위험 우선순위, 스모크 테스트, 파일 경계 제안만 보고.
- **P-C1 (승인 후)**: 동일 화면/기능 조건으로 `data / state / repository / render / action handlers / styles` 분리. 한번에 한 덩어리, import/이벤트 중복과 경로·file:// 회귀 확인.
- **P-C2 (승인 후)**: A3 `publishedSnapshot` 스키마 소비할 adapter만 설계, 원본 환자 v1.2와 B2B2C 통합/연동은 별도 승인.

## Codex 절약형 작업 계약
1. 기준본 해시·파일수/구조 먼저 보고, 위험도 기준으로 변경 범위를 명시.
2. 첫 턴에는 기능 개선·디자인 교체 **하지 말고**, 핵심 함수만 `rg`/구간별로 살펴 진단 및 테스트 작성 계획 제출.
3. 기존 동작/문구/타이포·색상/반응형/로컬 저장 의도적 변경 금지.
4. 이후 1~2개 기능 단위만 별도 변경, 항상 이전 테스트와 스크린샷 비교. 실패 시 롤백하고 PASS/FAIL/NOT RUN 구분.
5. 개인 정보, 원격 앱, 가상 코드 로그인 등을 실제 인증/의료기록 전송으로 확장하지 말 것.
