## 1. v0.2 기준 구조와 변경 경계

### 1.1 실제 확인한 구현

- `index.html` + `styles.css` + `app.js` + `data.js` + `workflow.js`; `build_standalone.py`가 독립 `preview.html` 생성.
- A1은 가상 환자 선택 대화창, A2는 **A3 번들 내부에서 복제 구현한 30항목 평가 실험 화면**, A3는 실제 편집·검토·승인·발행 시뮬레이션, B는 독립 미리보기 화면.
- `REPO_KEY = 'a3-prototype-v02-synthetic-only'`; 일부 선택 상태와 승인/발행 이력은 브라우저 로컬 저장, 첨부 PDF 바이트는 세션 메모리만 사용.
- `issuesFromValues`는 필수 누락/상충 및 `medication.reconciliation='conflict'`를 검토 이슈로 생성하고, `blockers`는 미해결 이슈·필수 공개 항목·미검토 PDF를 별도 검사.
- SYN-001의 초기 ‘7건’은 **이슈 1개 + 미검증 환자 공개 계획 6개**로 시연 가능하나, 향후 항목/자료 상태에 따라 **동적으로 변함**. 7을 고정 텍스트로 넣지 않는다.
- `currentPublished`와 `makeRevision` 등의 기존 상태/버전 경로를 유지하며 v0.3에서 데이터 스키마 확장 시 불변조건을 추가 검증.

### 1.2 변경 금지

1. 승인된 원본 `prototypes/hospital-a2/`의 디자인과 6영역·30항목·평가 엔진 변경 금지. A3 복제 화면과 원본이 완전히 동일하다고 주장 금지.
2. 환자용 v1.2 수정·교체·통합 금지.
3. 사용자 승인 없이 GitHub에 커밋/푸시/PR/배포 금지.
4. 실제 환자·병원 문서 또는 개인정보 입력/저장/업로드 금지.
5. 0~3등급을 발행 허가·의학적 안전 판정으로 승격 금지.

## 2. 상단 UI: 정보 구조·치수·반응형

### 2.1 데스크톱 정보 위계

```text
[사이드바]  A3 퇴원 후 관리계획                       [초안 v0.1] [저장 상태]

            ┌────────────────────────────────┬────────────────────────┐
            │ 환자 정보 (60%)                 │ 해결 필요 (40%)         │
            │ 이정희 · 75세          [선택▼]   │ ! 발행 전 확인 7건       │
            │ SYN-001 · 근골격계 수술 후 퇴원   │ [7건 확인 →]            │
            │ 퇴원 예정 2026-10-21            │                        │
            └────────────────────────────────┴────────────────────────┘

            6영역 판단 요약 [의료][간호][약료][기능][사회환경][연속성]

            [계획 편집] [근거·미해결] [PDF·첨부] [승인·이력]   [미리보기 열기]
            ┌─────────────────────────────────────────────────────────┐
            │ 편집 영역: 첫 항목만 펼침, 나머지 상태 보이는 아코디언    │
            │ 근거 선택·첨부·검토 상태와 다음 작업을 위계적으로 표시   │
            └─────────────────────────────────────────────────────────┘
                               [검토 요청 / 보완 / 승인 / 발행]
```

- 너비 비율은 `minmax(0, 3fr) minmax(18rem, 2fr)`부터 검토하고, 콘텐츠 폭·텍스트 길이에 따라 조정. **고정 50%가 목표가 아님**.
- 카드의 `min-height`는 약 **96~112px 출발점**으로 두고, 실제 텍스트가 늘어나면 자연 확장. 억지로 높이를 고정해 텍스트를 잘라내지 않는다.
- 카드 내부 여백은 16~20px 수준을 1차 출발점으로 하되 A2의 기존 밀도와 시각 비교 후 결정.
- 환자 선택은 환자 카드 오른쪽 끝에 통합. 같은 정보를 헤더/하단에서 반복하지 않음.
- 차단 카드 클릭 시 기존 ‘전체 항목 팝업 → 항목 클릭 → 대상 탭 및 포커스 이동’ 흐름 유지.
- **0건일 때** 과장된 녹색 배너를 남기지 말고 `발행 전 확인사항 없음`을 얇은 중립 상태로 표시. 승인 권한·상태가 충족되지 않으면 여전히 ‘발행 가능’이라고 단정하지 않음.

### 2.2 반응형 및 상태

| 가용 콘텐츠 폭 | 구성 | 주의점 |
|---|---|---|
| ≥ 920px | 상단 60:40 2열; 미리보기 기본 숨김 | 미리보기 켜면 작업 2열, 표·텍스트 자연 줄바꿈 |
| 680~919px | 상단 조건부 2열 또는 1열(내용 우선); 우측 미리보기는 접힘 | 긴 환자 문맥/선택 컨트롤에서 줄바꿈 검사 |
| < 680px | 상단 1열; 차단 카드 한 줄 제목 + 확인 버튼, 필요 시 두 줄 | 터치 목표 최소 44×44px, 가로 스크롤 금지 |

숫자는 **설계 시작값**이며 실제 A3 가용 콘텐츠 폭과 242px/78px 사이드바 동작을 320/390/800/801/1024/1440px에서 검증해 최종 토큰 조정. 모바일 A2는 기존 상단 내비게이션 정책 준수.

### 2.3 글자·시각 위계

- 페이지 제목 28~34px(반응형), 카드 섹션 제목 18~20px, 기본 본문 15~16px, 필드 레이블/버튼 14~16px, 자료 보조정보 12~13px 이하 최소화.
- 경고는 색상뿐 아니라 아이콘·명확한 제목·해결 동작 제공. 작업 완료/미확인 상태를 작은 연회색 글자에만 의존하지 않음.
- ID와 규칙 버전은 메인에서 숨기되 ‘상세 근거/기술 정보’에서는 접근 가능. 환자 ID `SYN-001`은 식별·가상 여부 확인에 필요하므로 유지.
- 현재 보이는 ‘저장 실패’는 레이아웃이 아니라 **저장 결과**이므로 숨기지 않는다. 실패 시 복구·재시도 경로를 제공.

## 3. 전체 내비게이션과 학습 구조

### 3.1 사이드바 IA

```text
A1  환자 목록
A2  다영역 평가
A3  계획 검토·발행
B   환자용 미리보기
────
?   사용법·학습   ← 신규 독립 화면
```

기존 상단 `사용 안내`는 ‘도움말’로 간소화하여 **현재 화면과 관련된 핵심 도움만** 팝업으로 보여준다. ‘학습에서 자세히 보기’로 독립 학습 탭의 해당 앵커로 이동.

### 3.2 학습 탭 5개 단원

| 단원 | 화면에 보여줄 것 | 인터랙션/학습목표 |
|---|---|---|
| L01 시작하기 | A1→A2→A3→B 과정, 시스템 역할/한계, 1분 빠른 실행 | 단계 클릭 시 실제 화면으로 이동, 현재 학습환자 유지 |
| L02 화면 읽기 | 상단 환자·발행 차단·6영역·계획카드·PDF·승인 상태의 예시 | 각 컴포넌트 ‘왜/어떻게/어디서 수정’ 안내, 해당 위치로 이동 |
| L03 원천자료 이해 | 읽을 수 있는 **가상 원천자료 카드**와 A2/A3 필드 연결 | 자료 열기→관련 사실/상충 설명→실제 근거 연결 화면으로 이동 |
| L04 케이스 실습 | SYN-001~004 카드, 목적/난이도/남은 과제/성공 상태 | 학습 세션 시작·힌트·진행/완료 확인·처음부터 다시하기 |
| L05 용어·FAQ | 원천자료, 스냅샷, 미평가, 상충, 검토, 승인, 발행, 철회, 버전, PDF | 검색/접힘 설명·현재 화면별 도움말과 교차 링크 |

단원에는 간결한 요약 → 시각적 예시 → ‘직접 이동/실습’ 순서를 적용. 사용자 화면에 장문의 목업 주석을 다시 늘어놓지 않는다. 검증된 임상척도가 아니라는 설명, 시연 한계, 실제 인증/연계 미구현 등은 **L01/L05**에 명확하게 제공.

| 위치 | 도움 내용 | 연결 |

## 4. 원천자료 모델 및 연결 UX

### 4.1 데이터 계약

```json
{
  "id": "SRC-SYN001-MED-01",
  "title": "퇴원약 목록 대조 기록",
  "patientId": "SYN-001",
  "encounterId": "ENC-SYN001-01",
  "domain": "medication",
  "fieldRefs": ["medication.reconciliation", "medication.medUnderstanding"],
  "sourceType": "mock_clinical_note",
  "observedAt": "2026-10-21T09:00:00+09:00",
  "verificationStatus": "PENDING",
  "summary": "퇴원약 대조의 완료 여부를 재확인해야 함",
  "documentVersion": "1",
  "isSynthetic": true
}
```

`sourceType`과 `verificationStatus`는 기록 유형과 진위/검토 수준을 구분하기 위한 용어이며, 실제 병원 원천 데이터가 존재한다는 의미가 아니다. 모든 예시 문서는 가상 자료다.

필수 속성: ID, 사람 읽기 제목, 환자+입원 건, 출처 종류, 대상 A2 필드 목록, 내용 요약, 기준 시각, 확인 상태, 문서 버전, 가상 여부. 권장 속성: 검토 직종, 대조 기록, 후속 회신·폐기 관계, 교육용 PDF 링크.

### 4.2 입력 동작(교체)

**기존:** `원천 기록 ID` 자유 입력 → 사용자가 `SIM-SRC-...` 같은 형식을 외워야 함.

**v0.3:** `관련 기록 선택` 클릭 → **현재 환자의 가상 자료 목록**(제목·영역·상태·날짜) → 기록 상세 열기 → `이 근거 연결` → 대상 필드 자동 채움 → 권한 있는 역할이 해결·검토.

- `sourceRef`는 직접 타이핑이 아니라 **존재하는 자료 선택**이 기본. 고급 모드에서 ID 표시/검색만 허용.
- `patientId`, `encounterId`, `fieldRefs`, 버전, 상태를 모두 검사. **다른 환자 자료, 무관한 필드, 확인 불가 문서 연결 거부**.
- 하나의 사실에 자료 A/B가 충돌하면 둘 다 표기하고, 선택만으로 해결 완료하지 않는다. 확인 기록 또는 유효한 새 회신 필요.
- 자료 연결과 `PlanItem.verified=true`는 다른 행동. 적합한 자료를 연결하더라도 의료진 검토를 거쳐야 한다.
- 자료 제목은 기본, ID·원천 시각·상세 연결은 확장 시 보임. 메인 화면에 개발자용 ID를 반복하지 않음.
- 학습용 텍스트는 구체적 약물 용량·처치방법·의학적 허가 범위를 임의 생성하지 않는다.

## 5. 환자 케이스 4개: 목표·시작 상태·조작·성공 정의

> A2 원본 데이터 3건(SYN-001~003)은 변형하지 않는다. **SYN-004는 A3 v0.3 패키지의 확장 시나리오 전용**이며 원본 A2 v0.5 환자 목록을 변경하지 않는다. A3 내 A2 실험 화면의 30항목 형식만 따르는 새 합성 값으로 구성.

### CASE 1 — SYN-001 (발행 전 보완, 중간 난이도)

- **출발:** A2 6영역 모두 등급 표시 가능하지만, 계획 6개 항목의 원천 기록 연결/검토 미완료 + 약료 기록 추가 확인 이슈. 기존 7건의 ‘발행 전 해결사항’ 흐름을 학습 목표로 사용.
- **제공 자료:** 약료 확인 기록, 간호 교육 기록, 기능 관찰, 가정 복귀 상담, 예약 확인, 문의 경로, 교육용 PDF.
- **사용자 행동:** `7건 확인` → ① 복약 이슈 선택 → ② 관련 기록 열기/검토 → ③ 원천자료 연결 → ④ 계획 내용/검토 상태 점검 → ⑤ 나머지 항목 순차 해결 → ⑥ 검토 요청/모의 승인/발행.
- **완료:** `blockers=0`, 각 공개 계획 항목에 유효한 해당 환자 기록 연결 및 직종 확인, 승인/발행 성공, 공개 스냅샷에 내부 ID·메모 미포함.
- **실패/힌트:** 확인 전 자료를 임의 ID로 입력하거나 해결 사유 없이 승인 시도 → 차단, 관련 학습 단원으로 이동.

### CASE 2 — SYN-002 (기본 발행, 쉬움)

- **출발:** A2 여섯 영역 0등급. 기본 퇴원계획 6개는 별도 가상 확인 자료를 갖춘 상태. 임상적 안전판정이 아니라 기본 발행 흐름을 배우는 사례.
- **사용자 행동:** 환자 선택 → 계획 내용/공개 범위 살펴보기 → ‘검토 요청’ → 역할 변경(시연) → 승인 → 발행 → B 화면에서 계획 확인 → PDF 인쇄 테스트.
- **완료:** 승인 이력·발행 스냅샷 존재, 계획 v1.0 표시, 약물명·용법·진료일정의 근거 없는 추가 자동생성 없음.

### CASE 3 — SYN-003 (누락·상충, 어려움)

- **출발:** 약물 기록 A/B 충돌 및 간호 교육, 기능 이동, 보호자 지원, 외래 항목 결측. **HARD 블로커가 남은 상태에서 승인·발행 차단**.
- **제공 자료:** 서로 충돌하는 약료 기록 A/B, 확인되지 않은 예약 메모, 누락 정보 확인 요청, 실습 중 순차적으로 열리는 가상 담당자 회신(C).
- **사용자 행동:** 문제 목록 → 충돌 근거 나란히 읽기 → 담당 역할 확인 → 필요한 가상 회신 자료 획득 → A2 입력 정정·A3 인계 → 해결 기록·계획 재검토.
- **완료:** 해결하지 못한 이슈가 남은 동안 승인이 계속 차단됨. 필요한 자료가 적법하게 모두 확인되면 그때에만 발행 경로 열림.
- **금지:** 사용자에게 상충 자료 중 마음대로 하나 선택해 ‘해결 완료’하게 하거나, 인계 없이 원천 사실을 덮어쓰기.

### CASE 4 — SYN-004 (발행 후 개정, 중간 난이도)

- **출발:** 새 가상 환자·입원 건에 대해 **기존 발행 v1.0 스냅샷**과 새로 수신한 외래 일정 확인서 1건을 포함한 시연용 초기 상태. A2 v0.5 기존 세 환자와 독립.
- **사용자 행동:** B에서 발행 v1.0 확인 → `새 버전 개정` → 신규 일정 근거 열기 → 계획 수정 → 재검토·승인 → 새 버전 발행 → 이전 버전 ‘대체됨’ 표시 비교 → 선택적으로 발행 철회 학습.
- **완료:** v1.0 내용·승인 시각은 변경되지 않고 v2.0 발행 시 이전 버전 `SUPERSEDED`, 새 버전이 현재 유효본. 실패 시 v1.0을 조용히 삭제/덮어쓰지 않음.

### 5.1 케이스 선택 카드 및 ‘실습 시작’

카드: `케이스 제목` / 가상 환자·ID / 학습 목표 / 난이도 / ‘예상 단계 수’ / `원천자료 보기` / `실습 시작` / `다시하기`.

- 학습 버튼은 **가상 학습 사본**을 생성하여 진행. 실습용 저장 키와 일반 편집용 저장 키 분리.
- 일반 작업 세션의 초안/승인/발행 이력을 절대로 자동 초기화하지 않음. 진행 중 상태가 있다면 학습 사본으로 전환됨을 명시.
- ‘완료’는 단순 버튼 클릭이 아니라 **실제 상태 변화**(유효 근거 연결, 게이트, 승인/발행 이력 등)로 계산.
- 힌트는 단계별로 공개(‘어느 탭’ → ‘어느 문서’ → ‘수행 동작’). 정답 자동 수행 버튼은 두지 않음.
- 학습 종료 후 원래 환자·작업 탭·미리보기 접힘 상태로 돌아올 수 있음.

## 6. 업무 인터랙션 상세

### 6.1 해결사항 팝업 → 실제 위치

1. 상단 compact 카드 클릭 또는 `N건 확인` → `<dialog>`.
2. 항목별 제목, 업무 분류(근거/계획/PDF), 해결할 동작, 연결된 자료 존재 여부 표시.
3. 항목 선택 → 팝업 닫힘 → 정확한 A3 탭으로 이동 → 접힌 편집 카드 자동 열림 → 대상 컨트롤 포커스 및 스크롤 맞춤.
4. 자료가 필요한 항목은 해당 원천자료 선택기를 바로 열 수 있음.
5. 검토 완료 시 N건을 즉시 재계산. **차단 항목과 참고/알림 항목은 구별**.

블로커 ID로 대상 UI를 찾지 못하는 경우 경고/완료를 거짓 표시하지 않고, 탭으로 이동 후 원인을 기록. ESC/포커스 복귀/키보드 동작 포함.

### 6.2 계획 카드 밀도 조절

- 기존 6개 섹션과 작업 기능 유지. 기본 첫 섹션만 펼침.
- 접힌 제목 행에도 `검토 필요/검토 완료`, 자료 연결 수, 공개 범위의 핵심 상태 노출.
- 근거 상세는 2차 공개, 문서 ID/규칙 디버그 필드는 3차 공개.
- 우측 환자 미리보기는 처음엔 숨김. `미리보기 열기`→2열, `닫기`→편집 1열. B 독립 화면에서도 같은 환자·공개범위를 참조.
- 계획 초안 공개 예정 미리보기와 **발행된 유효 계획**을 명확히 표시·구분. 미발행 초안을 실제 공개본처럼 표시하지 않음.

### 6.3 PDF

- 가상 자료 PDF와 첨부 실제 PDF는 분리. 학습 탭에서 가상 자료 보기 가능하더라도 **A3 환자 공개 첨부로 자동 승인 처리하지 않음**.
- 환자 공개로 설정된 문서는 PDF 내용 확인 + 검토 완료 + 해당 환자·계획 버전 일치가 필요.
- `브라우저 인쇄→PDF 저장` 기능은 유지하지만 발행 완료의 증거로 사용하지 않음. ‘서버 영구 저장·원자적 발행’은 **NOT IMPLEMENTED**로 학습 탭에 표시.
- 사용자 선택 PDF가 메모리 소실로 없어지면 미검토/원본 부재 차단을 유지. 학습 자료로 제공되는 기본 PDF와 업로드한 임시 첨부를 분리해 관리.

## 7. 상태·저장·보안 계약

### 7.1 상태 전이 유지

`DRAFT → REVIEW_REQUESTED → APPROVED → PUBLISHED`; 보완은 `CHANGES_REQUESTED → DRAFT`; 발행 후 새 초안 `REVISION` 및 기존 발행본 `SUPERSEDED`/`REVOKED`.

- A2 변경 시 원본 스냅샷 유지, **명시적 인계**; 검토·승인 무효화.
- 새 근거 선택이 계획의 필수 사실에 영향을 주면 기존 검토 플래그를 무효화하거나 재검토 필요 상태로 전환.
- 이미 발행된 계획·PDF·감사기록은 편집할 수 없는 스냅샷으로 유지.
- 문서 첨부·원천기록의 환자/입원 건 불일치, 확인되지 않은 내용, 미해결 상충은 HARD 게이트.
- 평가 0등급이어도 기본 계획 작성/공개 확인은 생략하지 않음.
- `reviewer` 역할 모의 선택은 **실제 사용자 인증·인가가 아님**. 위험 제한은 프런트엔드 시연용일 뿐.

### 7.2 저장 및 마이그레이션

- v0.2 저장 키를 덮어쓰지 않도록 **v0.3 네임스페이스로 분리**. 기존 v0.2의 세션과 이력 자동 변환 금지.
- 학습 진행: `learningSession` 별도 키, 학습용 환자 기록 사본, 튜토리얼 진행상태/선택 미션 기록. 저장 실패 시 완료했다고 표시하지 않음.
- 시작·환자 변경·탭 이동·페이지 복원 시 기존 편집 내용을 보존. 초기화는 **해당 환자/학습 세션 범위**에만 영향을 미침.
- 내부 소스·담당자·감사정보가 환자 공개 스냅샷에 포함되지 않도록 화이트리스트 유지.
- 실제 PDF 파일은 localStorage에 base64로 저장하지 않음. 기존 메모리 기반 첨부 제한을 명시하고, 새로고침 후 원본 부재에 대한 차단 유지.

**Codex 기본 정책:** 해당 단계의 파일만 선별 읽기 → 변경 전 위험 파악 → 최소 수정 → 해당 테스트 → 최종 회귀. 다른 단계 선행 구현 금지. AGENTS.md가 있으면 읽고 따르되 전체 저장소·레퍼런스 파일 일괄 선독 금지. GitHub 작업은 별도 승인 전 수행 금지.

### 현재까지 확인한 ‘기존 부채’(후속 단계에서 검토)

- A3 내부 A2는 승인 원본 A2 v0.5의 별도 복제본 → 장기적으로 규칙 이중관리/드리프트 위험. **v0.3 단계에서는 원본 변경하지 않되 차이 테스트**.
- 원천기록은 현재 자유 입력 ID → 존재/필드/환자 일치 검증 부재. v0.3 우선 보완.
- `fingerprint`는 브라우저 로컬의 단순 해시이므로 **암호학적 서명 아님**. 실제 인증/감사보안으로 승격 금지.
- `localStorage`·인메모리 PDF가 결합된 구조는 새로고침/첨부 무결성 문제를 초래. PDF 실제 발행 트랜잭션은 장기 과제.
- v0.2는 HTTP 직접 탐색 테스트 미실행. 재현 가능한 환경을 확보해야 함.

## 10. 수용·변경 관리

### v0.3 설계가 의도하는 ‘완료된 시연’

- 상단에서 **환자 식별과 발행 장애를 한 번에 읽고** 바로 해당 작업으로 이동할 수 있음.
- 설명을 처음부터 읽을 사람은 학습 탭을, 실제 업무 중 막힌 사람은 빠른 도움말을 사용함.
- `원천자료 ID`를 외울 필요 없이, 관련 실제 **가상 예시 자료**를 열고 근거를 연결할 수 있음.
- 4개 합성 사례는 학습 목표·시작 상태·성공 판정이 달라 반복 시연 가능.
- 기존 A2 승인 디자인, 평가 규칙, A3 승인/발행의 차단 조건 및 환자용 v1.2 원본은 영향받지 않음.

### 승인 구분

- **사용자가 승인한 것:** 설계서 작성 진행, v0.3의 설계 검토 착수.
- **아직 별도 승인이 필요한 것:** v0.3 코드 구현·Codex 실행, GitHub 저장소 반영, A2 원본 통합, 환자용 v1.2 수정/통합, 임상·보안 실서비스 확장.
