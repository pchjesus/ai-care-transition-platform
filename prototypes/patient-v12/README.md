# 퇴원 후, 나의 하루 — 모바일·PC UX 시연 v1.2

이 프로젝트는 간호 창업 과제용 **가상 퇴원환자 데이터**만 사용하는 정적 프런트엔드 시안이다. 실환자정보, 의료기관 API, Firebase 및 실제 본인인증은 없다.

## 사용하기

1. **환자용 앱:** `index.html`을 Chrome·Edge 등 JavaScript 사용이 가능한 브라우저에서 열어 실행한다.
2. 코드 `CARE2026`를 입력하고 **가상 환자 안내 시작** 버튼을 **한 번** 누르면 바로 환자 홈으로 이동한다. 별도의 환자 선택 클릭은 필요 없다(환자는 가상 1명).
3. '글자 크게'는 오늘/일정/도움/상세/문제/전체계획/내 정보에 공통 적용되며 같은 브라우저에서 설정을 기억한다.
4. '내 정보' → '주소·연락처 수정하기' → '수정 내용 저장' → 확인 팝업 '변경사항 저장'을 누르면 가상 수정 정보가 **브라우저 localStorage**에 저장된다.
5. 저장 후 '정보 업데이트 전송 요청' → 시연 동의 체크 → '모의 전송 요청 기록'을 누르면 **이 브라우저 안에만 모의 요청 기록**이 남는다. **실제 기관으로 전송하지 않는다.**
6. `preview.html`은 별도의 개발·의료진 시연 화면으로 발행/철회/초기화 등의 시연 기능을 지원한다.
7. 보행보조기 자료는 앱 내부에서 미리보기·PDF 저장 등을 시험할 수 있다. PDF는 실제 진료 지시가 아닌 예시다.

**중요:** 파일을 미리보기로만 보여주는 서비스가 HTML 내부 JavaScript 실행을 막는 경우 버튼이 동작하지 않을 수 있다. 해당 환경에서는 ZIP을 내려받아 파일을 추출한 뒤 `index.html`을 Chrome/Edge에서 연다. 이 환경에서도 차단되면 임의로 개인정보를 입력하지 말고, 로컬 정적 서버 또는 허용된 개발환경에서 시험한다.

## v1.1 대비 수정

- 잘못된 체험 코드 → 오류 표시; `CARE2026` → 별도 2차 선택 없이 바로 홈 진입.
- 부분 적용이던 글자 확대 → **전체 앱의 CSS 텍스트 크기 배율**로 통합(기본 대비 약 18% 확대, 일부 개별 UI 스타일 고려).
- 정보 수정 → 저장 확인 → 브라우저 저장 → 별도 모의 업데이트 요청 흐름 명시.
- 브라우저 스토리지에 `(profile, revision, lastRequest)`를 일관되게 저장·복원하며, 새로운 수정은 과거 요청 상태를 초기화한다.
- 모의 요청 ID(예: `DEMO-0001`)·수정 revision·요청 상태를 기록한다. 같은 수정에 중복 시연 요청을 하지 않도록 요청 버튼 상태 처리.
- 내 정보 화면에서 저장 안내가 팝업과 화면에 이중으로 겹치는 중복 토스트를 제거.
- 기존 환자 홈/도움 검색/상세 안내/PDF/선택형 이해확인/모의 의료진 발행·철회 기능 유지.

## 실제 구현 vs 추후 구현

| 기능 | v1.2 | Firebase·병원 연동 이후 |
|---|---|---|
| 환자 접근 | 누구나 알 수 있는 시연 코드 | 신원확인 + 기관 환자 데이터 매핑 + 서버 권한 검증 |
| 주소·연락처 저장 | 브라우저 `localStorage`(가상자료만) | 인증된 계정별 서버 저장, 접근권한·감사로그 |
| 기관 전송 요청 | 이 브라우저 내부 `LOCAL_ONLY` 기록 | 서버 검증→기관 발송/수신/승인/반려/반영 분리 |
| 가상 의료진 승인 | `preview.html` 시연 상태 | 실제 의료진 인증·승인 이력·공개 스냅샷 |
| PDF | 합성 PDF 이미지 및 원본 포함 | 기관 승인 문서 및 버전·접근권한 검증 |

**실명, 실제 전화번호, 병원 환자번호, 주민등록번호 또는 민감 진료정보를 이 앱에 입력하지 말 것.** 현재 저장 방식은 실제 의료정보의 보안에 적합하지 않다.

## 파일 관리

- `app.js`·`styles.css`: 수정 가능한 소스. 변경 후 `python build_standalone.py` 실행.
- `index.html`·`preview.html`: 각각 CSS/JS/PDF를 포함한 독립 실행 결과.
- `보행_보조기_안내_시연용.pdf`: 원본 참고 샘플.
- `FIREBASE_INTEGRATION_CONTRACT.md`: Firebase 전환 시 필요한 책임·상태·권한 설계.
- `test_v12.py`: Chromium Playwright 화면·기능·상태 회귀 테스트. **브라우저의 파일/localhost 직접 접속이 차단된 테스트 컨테이너에서 HTML 주입 및 저장소 모의 방식**으로 검증한다.
